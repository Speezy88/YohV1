Yoh — Color & Material Theme Exploration

Five register variations for the Phase 2 web app Home page, built from the PRD-fixed constraints (off-white + black base, neumorphic surfaces) plus the session's added direction: a mix of neumorphism and glass/translucency, inspired by Meta's Muse and Apple's translucent material language, targeting "high-tech but minimalistic" and "miles better than any other AI product." No emoji anywhere. Each variation differs in register, not hue — and each prints real WCAG 2.2 contrast numbers so the open question ("can off-white neumorphism pass AA?") has an honest answer per variation.

Wordmark note: "Yoh Meeseek" is requested in bold Montserrat. This page loads nothing from the network, so it declares font-family: Montserrat, system-ui, sans-serif — it will render in the system UI font here unless Montserrat happens to already be installed locally.

Non-color cues used throughout (per WCAG 1.4.1 — never color alone): a checkmark glyph + strikethrough + reduced opacity marks "done" (not just a color swap); "Pinned" is a text tag, not a color dot; the fixed calendar event is both cross-hatched and labeled "(fixed)"; the in-drag block gets a dashed outline and is labeled "(dragging)"; Approve is always solid-filled, Discard is always outline-only — the shape difference carries the meaning even for a variation with zero accent color.

4 · Monochrome + one quiet accent same restraint as #3, plus a single muted indigo reserved for focus, active-drag, and Approve only

#EFEFEC bg/surface
#111111 body text
#6A6A69 muted text
#5B5B5A border/rim
#3454B4 accent
Computed WCAG 2.2 contrast (relative-luminance method)
PairRatioThresholdVerdict
Body text on surface16.39:1≥4.5:1PASS
Muted text on surface4.70:1≥4.5:1PASS
Control boundary (hairline) vs surface5.90:1≥3:1PASS
Accent vs surface (non-text)5.93:1≥3:1PASS
Accent-text on accent fill (Approve label)6.83:1≥4.5:1PASS

Boundary solution: same neutral hairline as #3 (#5B5B5A, 5.90:1) for default/rest state. The one difference: when a control becomes interactive (focus, active-drag, Approve) the border swaps entirely to the accent, so color adds a second, non-shadow signal on top of shape/weight rather than being the only cue. Why indigo: reads as "confirm/trustworthy" without copying Apple's exact system blue, stays low-saturation enough to not break monochrome discipline, and can't be confused with a destructive-red state.

5 · Inverted / dark (exploratory — dark mode is currently UNDECIDED) near-black glass + soft dark neumorphism, so this pass can judge whether dark mode belongs in scope at all

#16171A bg
#1E2024 surface
#EDEDEC body text
#909192 muted text
#707070 border/rim
#6E85E0 accent
Computed WCAG 2.2 contrast (relative-luminance method)
PairRatioThresholdVerdict
Body text on surface13.93:1≥4.5:1PASS
Muted text on surface5.17:1≥4.5:1PASS
Control boundary (rim) vs surface3.29:1≥3:1PASS
Accent vs surface (non-text)4.73:1≥3:1PASS
Accent-text on accent fill5.26:1≥4.5:1PASS

Boundary solution — the honest finding of this whole set: a genuinely soft dark rim (rgba(255,255,255,.12), closer to the "soft dark neumorphism" brief) measures under 2:1. Reaching 3:1 needed a near-solid mid-gray rim (#707070) — that reads as a visible stroke, not a subtle neumorphic edge, which directly fights the softness the brief asked for. Of all five variations, this is the one where the soft-shadow-boundary problem is worst and the supplemental cue is most visually assertive.
