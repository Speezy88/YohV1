- (insight by user) Existing Tasks DB fields: Task name, Area, Chunk Size (min/d), Due Date, Energy, Estimated Duration (min), Linked Project, Priority, Status. Actually-used subset: Estimated Duration, Area, Due Date, Status, Energy. Other DBs: Projects DB, Research Vault DB
- (decision by user) Projects DB = organizational grouping only (sort tasks/notes by project), not a planning input. Research Vault = on-demand output store when Yoh is asked to research a topic, not a planning input. Daily plan is driven by Tasks DB alone.
- (idea by user) Priority should be intuitive/derived, not manually set: prioritize larger/harder tasks first, and tasks with closer due dates
- (decision by user) Data completeness gate: Yoh should proactively ask the user to fill in missing required fields on tasks (e.g. no due date/duration/energy) rather than silently defaulting or letting them rot
- (idea by user) Night ritual: Yoh keeps retrying via notifications/speaker call-out until completed; if never completed, it flags 'you never checked in' and resolves any mandatory blockers during the next morning ritual instead
- (idea by user) Escalating retry capped at 2: retry 1 = phone notification, retry 2 = home speaker call-out; no further retries after that
- (decision by user) Asymmetric fallback: morning = single push then leaves user alone for the day; night = escalating 2-step retry (notification, then speaker call-out)
- (idea by user) Daily time budget is user-declared and changeable anytime by voice/chat (e.g. 2.5hrs one week, 4hrs another); Yoh can proactively suggest raising the week's workload if there's a known big push, but doesn't silently override the stated budget
- (idea by user) Default rhythm for filling the daily budget: 70 minutes work / 15 minute break, repeating, unless the user overrides
- (idea by user) Break count scales with total budget (e.g. 3hrs = 2 breaks); hard rule: no work chunk exceeds 70 minutes without a break; breaks should be intuitively/evenly spaced, aligned to boundaries between different task chunks rather than a rigid clock
- (decision by user) Correction: breaks are strictly clock-based, not task-boundary-based — no work push exceeds 70 minutes without a 15-minute break, even if that splits a single task mid-task
- (decision by user) Budget persists as whatever was last stated, applied every day (including weekends) with no automatic weekend default; rest days are explicit user declarations, not inferred
- (decision by user) Memory model is dual: (1) factual recall of what's been said/entered (notes, reminders, conversations) and (2) constantly-learning behavioral pattern recognition, like a real personal assistant getting to know the user over time
- (decision by user) Learned patterns are surfaced to the user for confirmation before Yoh acts on them — a 'propose, don't impose' rule, consistent with the earlier budget-override rule from the Plan Granularity axis
- (decision by user) Hybrid memory architecture chosen: small 'active' memory (recent days, current patterns, standing preferences) is front-and-center for every planning decision; full raw history lives in a 'cold' database, queried on demand rather than loaded by default, and gets distilled into short pattern-statements over time rather than replayed in full
- (idea by user) Hardware plan: Raspberry Pi (already owned) + 3D printed case + screen showing the web app, kept in the bedroom away from water; audio output goes via Bluetooth to a waterproof speaker in the bathroom
- (note) Parked for later: bathroom-side mic/input solution for the Bluetooth speaker — revisit after the bedroom device design is settled
- (idea by user) Idle/passive state: a passive clock view rendered as a small, non-distracting red light/display — sleep-friendly, doesn't disrupt the bedroom at night
- (idea by user) Mic-mute voice command phrase: 'Yoh, headphones' (mutes/stops active listening)
- (idea by user) Resume-listening phrase: 'Yoh, headphones off'

- (decision by user) Room-cleanliness camera check (future feature) runs automatically every 3 days, folded into an existing ritual rather than a separate trigger
- (idea by user) A task that slips (not completed) gets an automatic small priority bump for the next day, but capped so a low-priority task can't jump to high priority from slipping alone
- (idea by user) The slip-bump stacks: each consecutive day a task slips again, it gets another bump (escalating urgency over time, still within the cap)
- (decision by user) Blocker handling is logistics-only: Yoh reschedules/rearranges the plan around a blocker rather than trying to problem-solve the underlying blocker itself
- (decision by user) Adjustment/re-flow can happen mid-day in real time, not just at the night check-in (e.g. task finishes early or runs long)
- (decision by user) Mid-day re-flow is user-initiated only (self-reported progress) — Yoh does not proactively ping/check in mid-block
- (decision by user) Default tone: casual, peer-level secretary — organizes tasks and hands over a plan to execute, not formal
- (decision by user) For intellectual/academic questions: switch to concise, educational tone; explicitly avoid contrast framing (e.g. 'it's not just X, it's Y') as a structural crutch
- (decision by user) Tone escalates to more authoritative/urging when the user is slipping/procrastinating — ties directly to the slip-bump mechanic from the Adjustment Logic axis
- (idea by user) Selectable fun voice packs (robot voice, Hulk, Morty from Rick and Morty, etc.) as personalization options, but the primary/default voice stays casual and normal
- (decision by user) Voice packs are strictly manual/on-demand toggle, decoupled from tone-escalation logic — the authoritative/casual tone shift always uses the default voice, never auto-switches character voices
