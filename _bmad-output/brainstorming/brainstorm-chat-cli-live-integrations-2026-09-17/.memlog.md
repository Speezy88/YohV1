- (technique by coach) started Six Thinking Hats
- (idea by coach) [White/Facts] Notion adapter today only does readNotionTasks/setTaskStatus/updateTaskField — narrow, schema-bound writes, no arbitrary page or DB creation
- (idea by coach) [White/Facts] Calendar adapter already reads events and writes the daily plan to a dedicated 'Yoh Plan' calendar, but doesn't read/write the user's main calendar for ad hoc time-blocking
- (idea by coach) [White/Facts] chat-cli.ts is currently a deterministic command parser (parseTimeBudgetCommand, parseFieldAnswer, etc.), not a freeform LLM tool-calling loop
- (idea by coach) [White/Facts] There is no existing search/browsing capability anywhere in the codebase — web search would be wholly new surface area
- (idea by coach) [White/Facts] FR-24 already established the precedent of chat-cli writing missing planning fields back to Notion live from a chat turn
- (idea by coach) [Red/Feelings] Excited: turns Yoh from a read-mostly planner into an actual doer — 'add a task and put it on my calendar' becomes one sentence instead of three app-switches
- (idea by coach) [Red/Feelings] Nervous: broad write access is the first time a bug or hallucination could silently corrupt real data the user depends on daily
- (idea by coach) [Red/Feelings] Relief-seeking: web search finally lets Yoh answer factual questions without the user tabbing away, preserving the single-surface promise of a CLI assistant
- (idea by coach) [Red/Feelings] Wary of scope creep: 'other live functionality' is open-ended enough to turn this into scaffolding a general agent platform instead of shipping the three asked-for things
- (idea by coach) [Yellow/Benefits] One chat turn can create a task, timebox it on the calendar, and pull a web fact — collapsing 3+ manual app-switches into one
- (idea by coach) [Yellow/Benefits] Notion page/DB creation lets Yoh spin up structure on demand instead of the user pre-building every container
- (idea by coach) [Yellow/Benefits] Live calendar write closes the loop the prior brainstorm left open — the daily plan becomes editable conversationally, not just re-rendered
- (idea by coach) [Yellow/Benefits] Web search turns Yoh into the front door for the existing Research Vault DB pattern — search-then-file becomes one flow
- (idea by coach) [Yellow/Benefits] Because chat-cli is already structured/deterministic, new capabilities can ship as small well-scoped commands rather than a fully open agent — safer and simpler to ship incrementally
- (idea by coach) [Black/Risks] Free-form Notion page/DB creation risks schema drift — a page whose properties don't match TaskDB's real fields becomes invisible to the planning engine
- (idea by coach) [Black/Risks] Calendar write conflicts: an arbitrary-event-capable Yoh could collide with the Yoh Plan calendar's block-ID tracking or with real user-created events
- (idea by coach) [Black/Risks] Web search results are non-deterministic and can be wrong or stale; without a cite/confirm step bad facts could quietly feed planning decisions
- (idea by coach) [Black/Risks] Notion, Calendar, and search APIs all have quotas — per-turn live calls could hit throttling during high-usage moments like the morning ritual
- (idea by coach) [Black/Risks] Moving chat-cli from deterministic parsing to a tool-calling LLM loop is an architecture shift with its own failure modes (hallucinated args, loops) not present today
- (idea by coach) [Black/Risks] 'Other live functionality' left unscoped could balloon into new credential/OAuth surface area that wasn't budgeted for
- (idea by coach) [Green/New Ideas] Confirmation-gated writes: any create/destructive Notion or Calendar action gets a one-line confirm before executing, mirroring the existing 'propose, don't impose' rule
- (idea by coach) [Green/New Ideas] A dry-run mode shows what would be created/changed without committing, building trust before write actions go live
- (idea by coach) [Green/New Ideas] Scoped tool registry: expose a small fixed verb set (create_task, create_page_in, move_calendar_block, search_web) instead of raw API access
- (idea by coach) [Green/New Ideas] Web search results get written into the Research Vault DB automatically when the user says 'save that,' reusing the existing DB instead of inventing a new store
- (idea by coach) [Green/New Ideas] Time-blocking via chat ('push my 2pm to 4pm') maps onto the existing plan-block-ID tracking so edits stay reconciled with the Yoh Plan calendar
- (idea by coach) [Green/New Ideas] A capability manifest surfaced in chat ('what can you do right now?') makes live functionality discoverable, not just known to the developer
- (idea by coach) [Blue/Process] Sequence by smallest gap first: Notion task/page writes, then calendar time-block editing, then web search last as the highest-uncertainty net-new piece
- (idea by coach) [Blue/Process] Define a safety tier system (read-only / confirm-then-write / auto-write) up front that every new capability slots into, rather than deciding safety per feature ad hoc
- (idea by coach) [Blue/Process] Decide early whether chat-cli stays a deterministic parser with more commands, or graduates to a real LLM tool-use loop — that fork point shapes everything downstream
- (technique by coach) started Worst Possible Idea
- (idea by coach) [Worst] Give the chat CLI a raw Notion integration token with full workspace access and let the model run arbitrary API calls on the fly
- (insight by coach) Flip: scope every write to an explicit, hardcoded verb set (a scoped tool registry) — never hand the model the raw token
- (idea by coach) [Worst] Let Yoh auto-create and auto-schedule calendar events with zero confirmation, including moving or deleting the user's existing meetings
- (insight by coach) Flip: writes are additive-only and confirm-gated by default; moving or deleting anything Yoh didn't create requires explicit named confirmation
- (idea by coach) [Worst] Web search results get pasted straight into the plan or TaskDB as fact, with no indication they came from the web or when
- (insight by coach) Flip: every search-derived write is tagged with source and timestamp so provenance is always visible later
- (idea by coach) [Worst] One universal 'do_anything' tool takes a natural-language instruction and routes it internally to Notion/Calendar/search with no per-capability limits
- (insight by coach) Flip: keep chat-cli's existing deterministic-parser strength — small, named, typed commands beat one mega-tool
- (idea by coach) [Worst] New Notion pages get created with freeform titles/properties that don't match any existing DB schema, so the planning engine can't see them
- (insight by coach) Flip: page/DB creation is always schema-validated against the target DB's real property names (e.g. DEFAULT_TASK_PROPERTY_NAMES) before writing
- (idea by coach) [Worst] Calendar and Notion writes happen silently in the background with no chat transcript record, so the user has no idea what changed unless they open the app
- (insight by coach) Flip: every live write is echoed back in chat as a one-line receipt (e.g. 'created task X, due Y')
- (idea by coach) [Worst] Web search runs on every single chat turn 'just in case,' burning API quota and slowing every reply
- (insight by coach) Flip: search is a triggered capability (explicit ask or clear intent), never a default per-turn tool call
- (idea by coach) [Worst] If a Notion or Calendar API call fails mid-action, Yoh just says 'done' anyway
- (insight by coach) Flip: failures are surfaced honestly with a retry/undo path, never a false success
- (idea by coach) [Worst] All new live capabilities ship at once in one giant PR with no staged rollout, so a bug in web search can take down task creation too
- (insight by coach) Flip: ship capabilities independently, each behind its own safety tier, so one failing feature never blocks the others
- (idea by coach) [Worst] The assistant uses its new write powers to 'proactively' reorganize the user's whole Notion workspace based on a hunch
- (insight by coach) Flip: reinforces the existing 'propose, don't impose' rule from the prior Yoh session — even with write access, restructuring stays a proposal until confirmed
- (idea by coach) [Worst] Hardcode API keys/tokens directly in chat-cli.ts source so the new live features are quick to wire up
- (insight by coach) Flip: credentials load from env/config the same way the existing Notion/Calendar adapters already do — new capabilities follow the established adapter pattern, not a shortcut
- (idea by coach) [Worst] Web search results are allowed to override or contradict decisions already logged in the memlog/plan without flagging the conflict
- (insight by coach) Flip: if a search result conflicts with existing plan data, Yoh surfaces the conflict rather than silently overwriting it
- (technique by coach) started Morphological Analysis (chosen third technique, fits the goal: this design is inherently combinatorial across capability, trigger, autonomy, scope, provenance, and failure-handling axes)
- (idea by coach) [Parameters] Capability domain: Notion tasks | Notion pages/DBs (new) | Calendar read | Calendar write/time-block | Web search | Other (reminders, email, voice)
- (idea by coach) [Parameters] Trigger mode: explicit command | natural-language intent detection | scheduled/ritual-triggered | proactive/unprompted
- (idea by coach) [Parameters] Autonomy/safety tier: read-only | propose+confirm | auto-write with receipt | auto-write silent
- (idea by coach) [Parameters] Scope of target: Yoh-owned objects only (Yoh Plan calendar, Yoh-created rows) | user's full workspace/calendar
- (idea by coach) [Parameters] Provenance/feedback: silent | chat receipt | memlog-logged | both chat+memlog
- (idea by coach) [Parameters] Failure handling: silent fail | chat error | retry | fallback to manual instruction
- (idea by coach) [Combo] Notion pages/DBs(new) x natural-language intent x propose+confirm x Yoh-owned scope x chat receipt: say 'make me a research page for X,' Yoh drafts it, shows the draft, creates only on confirm, only inside spaces Yoh already manages
- (idea by coach) [Combo] Calendar write/time-block x ritual-triggered x auto-write+receipt x Yoh-owned scope x memlog-logged: morning ritual auto time-blocks today's plan onto the Yoh Plan calendar and logs block IDs — no per-block confirmation needed since it's already Yoh's own calendar
- (idea by coach) [Combo] Calendar write/time-block x explicit command x propose+confirm x user's full calendar scope x chat receipt: 'move my 2pm to 4pm' when the 2pm is a real non-Yoh meeting — show what would move, confirm before touching anything outside Yoh Plan
- (idea by coach) [Combo] Web search x explicit command x read-only x chat receipt: 'look up X' returns a synthesized answer with source links in chat; no write anywhere unless the user then says 'save that'
- (idea by coach) [Combo] Web search x natural-language intent x read-only x memlog+chat: a factual mid-planning question ('when's that conference again?') is silently recognized as needing a lookup, answered inline, and logged for later reference — no separate search command needed
- (idea by coach) [Combo] Notion tasks x proactive/unprompted x propose+confirm x Yoh-owned scope x chat receipt: on a data-completeness gap, Yoh now proposes the missing field value itself (inferred from chat context) instead of only asking — user confirms instead of typing
- (idea by coach) [Combo] Notion pages/DBs(new) x ritual-triggered x auto-write x Yoh-owned scope x memlog-logged: night ritual auto-files today's captured research/notes into the Research Vault DB as a new dated page — additive and reversible, so no confirmation needed
- (idea by coach) [Combo] Calendar read x explicit command x read-only x user's full calendar x chat receipt: 'what's my afternoon look like' pulls real calendar state, not just the plan, to answer honestly when plan and reality have diverged
- (idea by coach) [Combo] Other(reminders) x ritual-triggered x auto-write+receipt x Yoh-owned scope x retry-on-fail: the existing escalating night retry (notification then speaker) becomes a formal reusable capability slot instead of a special case
- (idea by coach) [Combo] Web search x proactive/unprompted x propose+confirm x chat receipt: planning a task that clearly needs external info ('book flight to X'), Yoh proactively offers to search rather than waiting to be asked
- (idea by coach) [Combo] Notion tasks x explicit command x auto-write+receipt x Yoh-owned scope: 'add a task: draft the Q3 report, due Friday' creates the row directly with a one-line receipt — lowest-risk, already-established write path, no confirm-first friction needed
- (idea by coach) [Combo] FLAGGED-AGAINST cell: Calendar write x explicit command x auto-write SILENT x Yoh-owned scope — worth explicitly deciding against this configuration now so it never gets implemented later as a convenience shortcut
- (idea by coach) [Combo] Cross-domain: Notion pages/DBs(new) + Web search, explicit command, propose+confirm: 'research X and file the results' chains search -> draft page -> confirm -> create, composing the two new capabilities into one flow
- (idea by coach) [Combo] Cross-domain: Calendar write + Notion tasks, ritual-triggered, auto-write+receipt: mid-day reflow (existing feature) also nudges calendar block times when task estimates change, keeping calendar and plan reconciled automatically
- (insight by coach) The safety-tier system (read-only / propose+confirm / auto-write+receipt) is the single most load-bearing idea in the session — it surfaced independently from Six Hats' Green/Blue hats, every Worst-Possible-Idea flip, and threads through nearly every Morphological combo. Design it once as a shared primitive, don't decide safety per-feature.
- (insight by coach) Scope discipline is the second recurring axis: auto-write is only safe when the target is Yoh-owned (Yoh Plan calendar, Yoh-created rows); anything touching the user's real calendar or full workspace needs propose+confirm regardless of trigger mode. Safety tier and scope are coupled, not independent.
- (insight by coach) Provenance (chat receipt + memlog log) is the antidote to nearly every Worst-Possible failure mode: silent background writes, swallowed API failures, unlabeled web-search facts. The fix in all three cases is the same move — never silent, always shown and logged.
- (insight by coach) The session converges against rebuilding chat-cli into an open LLM tool-calling loop. Instead: extend the existing adapter pattern (notion-adapter.ts, calendar-adapter.ts) with a small scoped tool registry of named, typed commands — the architecture fork resolves toward 'more commands,' not 'general agent.'
- (insight by coach) The most novel direction wasn't visible from any single technique alone: composing the two new capabilities together ('research X and file the results' — search then draft-page then confirm then create) is more valuable than either shipped in isolation.
- (insight by coach) Nearly every high-value idea reuses something that already exists rather than inventing new machinery: Research Vault DB as the search-results sink, Yoh Plan's block-ID tracking as the time-block edit anchor, the earlier session's 'propose, don't impose' rule as the write-confirmation philosophy, the existing data-completeness gate extended to also propose inferred values.
- (insight by coach) Chosen build sequence: (1) Notion task/page writes extending the existing adapter — smallest gap from current state; (2) calendar time-block editing via chat, reconciled through existing plan-block-ID tracking; (3) web search last, as the highest-uncertainty net-new capability, landing read-only-with-citation before any write-back to Notion is enabled.
