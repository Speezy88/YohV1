- (insight) [Red Hat] Never want the feeling that Yoh is 'stupid / not smart' - the effort invested must pay off as miles better than any other AI product
- (insight) [Red Hat] Every capability built must be exhibited at the highest level, right in front of the user, without the UI getting cluttered
- (insight) [Red Hat] 'Stupid' moment = planning without life context: scheduling an assignment right after school ignores commute, getting food, and other transition time
- (insight) [Yellow Hat] 'It gets me' = a valid daily plan aligned with actual work habits that also pushes toward being better and more organized
- (idea) Recurring daily time (commute, meals, routines) appears as blocks on the calendar; not everything is blocked
- (idea) Blocks on the Home calendar are easy to move to a better time directly (drag), building on FR-27 confirm-gated calendar editing
- (insight) [Black Hat] Failure mode 1: data too hard to input
- (insight) [Black Hat] Failure mode 2: plans too rigid instead of flexible
- (insight) [Black Hat] Failure mode 3: it breaks easily (reliability)
- (insight) [Black Hat] Break: chat doesn't close out a conversation when it naturally should
- (insight) [Black Hat] Break: Yoh hallucinates its capabilities - asks for data input that it was never going to store or use
- (insight) [Black Hat] Break: producing a terrible plan
- (insight) [Black Hat] Break: capabilities gated off by insufficient data - should instead do as much as it can with what it has (graceful degradation, not hard gates)
