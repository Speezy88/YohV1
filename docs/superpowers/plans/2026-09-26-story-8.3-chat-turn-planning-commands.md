# Story 8.3 — Chat Turn Routing for Planning Commands — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `chat-cli.ts`'s plan-view, Mid-Day Re-Flow, Blocker, Time Budget, why-prioritized, and general-question handling into one surface-agnostic `app/chat-turn.ts`, each capability its own `app/*.ts` file, so a future Web App turn (Task 6) and the terminal turn get identical answers from the same code. `llm-adapter.ts` gains a streaming variant of its general-Q&A call so a caller with a live stream sink (the server, later) can render deltas as they arrive; the CLI keeps using the existing non-streaming call.

**Architecture:** `app/chat-turn.ts` exports the one `chatTurn(deps, input)` entry point every non-slash chat line goes through (this story's slice; Tasks 5/8 extend its dispatch table). It runs the same deterministic recognizer checks `chat-cli.ts` used to run inline — now moved to `core/chat-commands.ts` — then falls through to Claude-classified general chat. Six new one-function-per-file `app/*.ts` modules (AD-16) hold the actual capability logic, moved verbatim from `chat-cli.ts` and adapted from "write to `io`" to "return a `ChatTurnResponse`." `chat-cli.ts` becomes thinner: it calls `chatTurn` once per non-slash line and renders whatever comes back (a reply, receipts, or an error message) with its own terminal styling — the app layer never emits ANSI.

**Tech Stack:** existing `node:test` conventions; `@anthropic-ai/sdk` (installed `0.120.0`) — `client.messages.create({..., stream: true})` returns a `Stream<RawMessageStreamEvent>`, which is itself `AsyncIterable<RawMessageStreamEvent>` (confirmed against `node_modules/@anthropic-ai/sdk/lib/MessageStream.d.ts` and `resources/messages/messages.d.ts`); no new package, no use of the SDK's separate higher-level `messages.stream()` helper (its `MessageStream` class carries far more surface — `.on()`, `.finalMessage()`, etc. — than this file needs).

**Spec:** `_bmad-output/planning-artifacts/architecture/architecture-YohV1-2026-08-22/ARCHITECTURE-SPINE.md` AD-1 (layering, Phase 2's `app/` insertion), AD-2 (functional core purity), AD-8 (`Result` at the core/adapter boundary; adapters/rituals throw or return `Result`, `app/` never lets a throw escape), AD-9 (file-level ownership), AD-16 (surface-agnostic interaction layer: one file per use-case, `(deps, input) => Promise<Result<Output, YohError>>`); `_bmad-output/planning-artifacts/epics.md` "## Epic 8", Story 8.3; `_bmad-output/implementation-artifacts/sdd-plan-YohV1-phase2-epic8.md` Task 4, plus contract sections C1 (row 4), C2 (`ChatTurnRequest`/`ChatTurnResponse`/`ChatStreamEvent`), C3 (`app/chat-turn.ts`, `app/time-budget.ts`, `app/plan-view.ts`, `app/mid-day-reflow.ts`, `app/blocker-report.ts`, `app/why-prioritized.ts`, `app/general-question.ts` rows).

This is not a Web/UX story — Task 4 touches no `web/*` file, so there is no Manual Verification checklist and no Playwright run in this plan's gate.

There is **no** search capability regression: a search-shaped line is still answered by the real `search-adapter.ts` call, through the exact same code as today.
   **Consequence, flagged for the controller (the accepted "temporary dispatch reorder"):** since the five recognizers this task owns (`parseTimeBudgetCommand`/`isPlanViewCommand`/`isMidDayReflowCommand`/`isBlockerReportCommand`/`parseWhyPrioritizedCommand`) now live *inside* `chatTurn`, reached only *after* `classifyChatIntent` returns `general-question`, a line like `"time budget 6h"` now costs exactly **one** Claude call (the classify call) before `chatTurn` recognizes and handles it deterministically — today it costs zero. 5. **`chatTurn` never itself emits a stream-terminal event (Controller ruling).** Across every one of its dispatch branches, the only `ChatStreamEvent` kinds `chatTurn` (or anything it calls) ever passes to `deps.emit` are `{type:"status", ...}` (its own `STATUS_THINKING`) and `{type:"delta", ...}` (relayed, unchanged, from `app/general-question.ts`'s streaming path) — it never constructs or emits `{type:"done"}` or `{type:"error"}` itself. The server (Task 6) is the one place that turns `chatTurn`'s returned `Result` into the stream's single terminal `done`/`error` event, after the last delta. Pinned by a dedicated test (Step 9.1) asserting every event emitted across every dispatch branch has `type` `"status"` or `"delta"`, never `"done"`/`"error"`.
6. **`ChatTurnResponse.reply` is ANSI-free by contract (C2), so Plan-view and Mid-Day Re-Flow/Blocker lose their terminal color.** `showPlanCommand` used to print `renderPlan(stored.data)` (color decided by `shouldUseColor()`); `midDayReflowCommand` used `runMidDayReflow`'s `rendered` (also color-capable, via `MidDayReflowDeps.color`). Content, wording, and wrapping are byte-identical; only the accent-header/muted-reasoning ANSI escapes are gone. This is invisible to every existing test (test runs are non-TTY, so `shouldUseColor()` already returns `false` there today) and only observable in a real interactive terminal session. **Accepted by the controller** — the CLI itself is retired in Story 8.9, so this is a bounded, temporary cosmetic loss, not a permanent regression.
7. **`chat-cli.ts` renders every `chatTurn` reply through the same `renderMarkdownForTerminal(reply, shouldUseColor())` call it already used only for general-question.** None of the other five capabilities' text contains markdown-special characters (`#`, `**`, `` ` ``) in practice, so this is content-preserving; it also converges the CLI toward the same "one generic render step for any chat reply" shape the Web client (Task 6) will use. **Accepted by the controller.**
8. **`why-prioritized`'s new `readTasks()` try/catch is a compelled fix, not scope creep.** Today, `runChatCli`'s why-prioritized branch calls `await readTasks()` with no try/catch — a live Notion failure there would throw out of `runChatCli`'s loop entirely (an existing latent bug). AD-8/Global-Constraints require `app/*` to catch adapter throws and convert them to `Result`; `explainPriority` is an `app/*.ts` file, so it must catch. **Accepted by the controller** as compelled by the layer's own rule, not an out-of-scope improvement.
9. **`app/mid-day-reflow.ts` becomes the one call site for `rituals/mid-day-reflow.ts`'s `runMidDayReflow` in all of `src/` (Controller ruling).** `app/blocker-report.ts`'s `reportBlocker` does **not** import/call `runMidDayReflow` itself — it calls a new, small exported wrapper, `runReflow(deps, {blockerReported})`, that `app/mid-day-reflow.ts` owns (this is the one place the literal identifier `runMidDayReflow` appears outside the ritual file itself). `reflowDay` also calls this same wrapper (with `blockerReported` omitted). This keeps `tests/mid-day-reflow.test.ts`'s existing structural "sole caller" test meaningful with a single-file answer instead of two — see Task 4/Step 4.5 for the exact test-file fix this requires (the test's own file-walk currently excludes *any* path ending in `mid-day-reflow.ts`, which would wrongly exclude the new `app/mid-day-reflow.ts` too unless that exclusion is narrowed to the ritual file specifically).
10. **`AnthropicMessagesClient.messages.create` overloaded** (non-streaming/streaming, matching the real installed SDK's own shape, `@anthropic-ai/sdk@0.120.0`) rather than adding a separate `stream()`-named method, so `createAnthropicMessagesClient`'s `return new Anthropic(...)` needs no change.

import { putTimeBudget, type MemoryStore } from "../adapters/memory-store.ts";
import { shapeDeclaredTimeBudget } from "../core/time-budget.ts";
import { localIsoDate } from "../rituals/ritual-shared.ts";
import type { ChatTurnResponse } from "../types/api.ts";
import type { Result, YohError } from "../types/domain.ts";

export interface TimeBudgetDeps {
  readonly store: MemoryStore;
  readonly timeZone: string;
  readonly now: () => Date;

  readonly totalMinutes: number;

/** Moved verbatim from chat-cli.ts's private helper — e.g. `360` -> `"360 minutes (6h)"`. */
function formatMinutesForDisplay(totalMinutes: number): string {
  const hours = totalMinutes / 60;
  const hoursLabel = Number.isInteger(hours) ? `${hours}h` : `${hours.toFixed(2).replace(/0+$/, "").replace(/\.$/, "")}h`;
  return `${totalMinutes} minutes (${hoursLabel})`;
}

export async function declareTimeBudget(
  deps: TimeBudgetDeps,
  input: DeclareTimeBudgetInput,
): Promise<Result<ChatTurnResponse, YohError>> {
  const today = localIsoDate(deps.now(), deps.timeZone);
  const shaped = shapeDeclaredTimeBudget({ totalMinutes: input.totalMinutes, date: today });
  if (!shaped.ok) {
    return { ok: false, error: { kind: "validation", message: `I couldn't set that Time Budget: ${shaped.error.message}` } };
  }
  putTimeBudget(deps.store, shaped.value);
  return {
    ok: true,
    value: { reply: `Got it — today's Time Budget is set to ${formatMinutesForDisplay(shaped.value.totalMinutes)}.`, receipts: [] },
  };
}

import { runMidDayReflow, type MidDayReflowOutcome } from "../rituals/mid-day-reflow.ts";
import type { MemoryStore } from "../adapters/memory-store.ts";
import type { ChatTurnResponse } from "../types/api.ts";
import type { Result, Task, YohError } from "../types/domain.ts";

export interface MidDayReflowAppDeps {
  readonly store: MemoryStore;
  readonly timeZone: string;
  readonly now: () => Date;
  readonly readTasks: () => Promise<readonly Task[]>;
}

export interface RunReflowInput {
  readonly blockerReported?: boolean;
}

export async function runReflow(
  deps: MidDayReflowAppDeps,
  input: RunReflowInput,
): Promise<Result<MidDayReflowOutcome, YohError>> {
  return runMidDayReflow({
    store: deps.store,
    readTasks: deps.readTasks,
    now: deps.now,
    timeZone: deps.timeZone,
    color: false,
    blockerReported: input.blockerReported,
  });
}

export async function reflowDay(
  deps: MidDayReflowAppDeps,
  _input: Record<string, never>,
): Promise<Result<ChatTurnResponse, YohError>> {
  const result = await runReflow(deps, {});

  if (!result.ok) {
    return { ok: false, error: { kind: result.error.kind, message: `I couldn't re-flow the rest of today: ${result.error.message}` } };
  }

  switch (result.value.status) {
    case "no-plan-today":
      return { ok: true, value: { reply: "There's no Plan for today yet to re-flow.", receipts: [] } };
    case "nothing-to-reflow":
      return { ok: true, value: { reply: "Nothing left to re-flow — everything remaining is already accounted for.", receipts: [] } };
    case "reflowed":
      return { ok: true, value: { reply: result.value.rendered, receipts: [] } };
  }
}

/**
 * src/app/why-prioritized.ts
 *
 * Story 8.3 (AD-16). Moved from `shell/chat-cli.ts`'s `whyPrioritizedCommand`.
 * Adds a `readTasks()` try/catch chat-cli.ts's original call site never
 * had — compelled by AD-8/the app/ layer's own rule that it must catch
 * adapter throws and convert to `Result` (this story's plan, Assumption 8).
 */
import { getSlipHistory, type MemoryStore } from "../adapters/memory-store.ts";
import { computeSlipBumpLevel } from "../core/slip-bump.ts";
import type { ChatTurnResponse } from "../types/api.ts";
import type { Result, Task, YohError } from "../types/domain.ts";

export interface WhyPrioritizedDeps {
  readonly store: MemoryStore;
  readonly readTasks: () => Promise<readonly Task[]>;
}

export interface ExplainPriorityInput {
  readonly taskName: string;
}

function describeError(err: unknown): string {
  return err instanceof Error ? err.message : String(err);
}

export async function explainPriority(
  deps: WhyPrioritizedDeps,
  input: ExplainPriorityInput,
): Promise<Result<ChatTurnResponse, YohError>> {
  let tasks: readonly Task[];
  try {
    tasks = await deps.readTasks();
  } catch (err) {
    return { ok: false, error: { kind: "unreachable", message: `I couldn't check why that's prioritized: ${describeError(err)}` } };
  }

  const normalized = input.taskName.trim().toLowerCase();
  const task = tasks.find((t) => t.title.trim().toLowerCase() === normalized);
  if (!task) {
    return { ok: true, value: { reply: `I couldn't find a Task named "${input.taskName}".`, receipts: [] } };
  }

  const history = getSlipHistory(deps.store, task.id);
  if (!history || history.data.consecutiveSlipCount <= 0) {
    return { ok: true, value: { reply: `"${task.title}" hasn't slipped recently — no Slip-Bump applied.`, receipts: [] } };
  }

  const { consecutiveSlipCount, lastSlipDate } = history.data;
  const level = computeSlipBumpLevel(consecutiveSlipCount);
  const dayWord = consecutiveSlipCount === 1 ? "day" : "days";
  const capNote = level.atCap ? " — at its Slip-Bump cap" : "";
  return {
    ok: true,
    value: {
      reply: `"${task.title}" has slipped ${consecutiveSlipCount} consecutive ${dayWord} (last slipped ${lastSlipDate}) — current Slip-Bump level ${level.value}${capNote}.`,
      receipts: [],
    },
  };
}

 * "never a silent empty reply" contract (AD-8) — throws if the stream ends
 * having yielded no text at all, or if `messages` is empty. Yields raw text
 * chunks (`content_block_delta` events whose `delta.type === "text_delta"`)
 * as they arrive; a caller with no live stream sink should keep using
 * `answerGeneralQuestion` instead (this file exposes both; `chat-cli.ts`
 * never calls this one — see `app/general-question.ts`).

export async function* streamGeneralQuestion(
  client: AnthropicMessagesClient,
  messages: readonly ChatTurn[],
  systemPrompt: string = DEFAULT_GENERAL_QA_SYSTEM_PROMPT,
  model: Anthropic.Model = CLAUDE_CHAT_MODEL_FAST,
): AsyncGenerator<string, void, void> {
  if (messages.length === 0) {
    throw new Error("llm-adapter: streamGeneralQuestion called with no conversation history at all");
  }

  const stream = await client.messages.create({
    model,
    max_tokens: CLAUDE_CHAT_MAX_TOKENS,
    system: systemPrompt,
    messages: messages.map((turn) => ({ role: turn.role, content: turn.content })),
    stream: true,
  });

  let sawText = false;
  for await (const event of stream) {
    if (event.type === "content_block_delta" && event.delta.type === "text_delta") {
      sawText = true;
      yield event.delta.text;
    }
  }
  if (!sawText) {
    throw new Error("llm-adapter: Claude returned no text content for a streamed general Q&A response");

export const MAX_CHAT_HISTORY_TURNS = 40;

/** Emitted first on every turn. Later tasks add their own capability-specific status constants (e.g. "Searching the web…") as they extend this dispatcher. */
export const STATUS_THINKING = "Thinking…";

export interface ChatTurnDeps {
  readonly store: MemoryStore;
  readonly timeZone: string;
  readonly now: () => Date;
  readonly readTasks: () => Promise<readonly Task[]>;
  readonly llmClient: AnthropicMessagesClient;
  readonly session: ChatSession;
  readonly emit?: (event: ChatStreamEvent) => void;
}

function trimHistory(history: readonly ChatTurn[]): readonly ChatTurn[] {
  let start = Math.max(0, history.length - MAX_CHAT_HISTORY_TURNS);
  if (start % 2 !== 0) start -= 1;
  return start <= 0 ? history : history.slice(start);
}

export async function chatTurn(deps: ChatTurnDeps, input: ChatTurnRequest): Promise<Result<ChatTurnResponse, YohError>> {
  deps.emit?.({ type: "status", text: STATUS_THINKING });

  const trimmedMessage = input.message.trim();
  if (trimmedMessage.length > 0) {
    deps.session.recentMessages.push(trimmedMessage);
    while (deps.session.recentMessages.length > RECENT_MESSAGES_WINDOW) deps.session.recentMessages.shift();
  }

  const timeBudgetCommand = parseTimeBudgetCommand(input.message);
  if (timeBudgetCommand) {
    return declareTimeBudget({ store: deps.store, timeZone: deps.timeZone, now: deps.now }, timeBudgetCommand);
  }

  if (isPlanViewCommand(input.message)) {
    return showPlan({ store: deps.store, timeZone: deps.timeZone, now: deps.now }, {});
  }

  if (isMidDayReflowCommand(input.message)) {
    return reflowDay({ store: deps.store, timeZone: deps.timeZone, now: deps.now, readTasks: deps.readTasks }, {});
  }

  if (isBlockerReportCommand(input.message)) {
    return reportBlocker({ store: deps.store, timeZone: deps.timeZone, now: deps.now, readTasks: deps.readTasks }, {});
  }

  const whyPrioritizedTaskName = parseWhyPrioritizedCommand(input.message);
  if (whyPrioritizedTaskName !== undefined) {
    return explainPriority({ store: deps.store, readTasks: deps.readTasks }, { taskName: whyPrioritizedTaskName });
  }

  // The sole fallback (Controller ruling): chat-cli.ts's own classifyChatIntent
  // call already ran, and already returned "general-question", before this
  // function was even invoked for this line — chatTurn does NOT re-classify.
  // Task 5 folds classify+search into chatTurn itself and this becomes a
  // real branch rather than the unconditional tail.
  return answerQuestion({ llmClient: deps.llmClient, emit: deps.emit }, { message: input.message, history: trimHistory(input.history) });
}
