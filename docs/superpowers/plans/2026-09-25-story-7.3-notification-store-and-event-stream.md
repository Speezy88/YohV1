# Story 7.3: In-App Notification Store and Live Event Stream — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A durable, dedicated-table notification store (AD-10, AD-18): any process (server or cron ritual) can raise a closed-`NotificationKind` in-app notification, atomically paired with a monotonic outbox row. `GET /api/events` tails that outbox over one SSE stream per client, hints only, with `Last-Event-ID` replay and a keep-alive comment on every poll tick. `GET /api/notifications` and a mark-read route expose them through `app/notifications.ts`.

**Architecture:** `adapters/notification-store.ts` owns two dedicated tables (`notifications`, `outbox`), created idempotently on first use, per AD-10 — never `memory-store.ts`'s generic blob table. Two low-level functions take the raw `better-sqlite3` handle a caller is already inside a `writeTx` with — `createNotificationInTx(db, input): string` (returns the generated id) and `appendOutboxInTx(db, {topic, entityId})` — so a caller spanning owners (Story 7.8's Plan write + outbox hint, Story 7.10's check-off commit) can call both inside its own single `writeTx`, never touching the `outbox` table directly (SDD plan Task 3 notes). A convenience `createNotification(connection, input)` wraps both in its own `writeTx` for the common single-owner case. `app/notifications.ts` is this story's first real `app/` use-case file — `listNotifications`/`markNotificationRead`, shaped `(deps, input) => Promise<Result<Output, YohError>>` per AD-16, which also gives `tests/layering-rules.test.ts`'s (Story 7.2) vacuous shape-check its first real file to check. This story also refactors `shell/server.ts`'s `createApp`/`app`/`startServer` (added zero-arg in Story 7.2, since it had nothing to depend on yet) to accept an `AppDeps` carrying the shared `SqliteConnection` — routes now need it. `GET /api/events` uses Hono's `streamSSE`, but the actual tail/replay/keep-alive loop lives in an independently-testable `runEventStream(stream, connection, options)` so tests drive it with an injected fake stream and a zero-length `sleep`/bounded `maxTicks` rather than a real multi-second wait.

**Tech Stack:** `hono/streaming`'s `streamSSE` (already available via the `hono` dependency Story 7.2 added), `better-sqlite3`, `node:crypto`'s `randomUUID`, `node:test`.

> **As built (implementer, 2026-09-26): deviations from the task code below.** The ACs, the spine, and controller rulings win where this plan's code disagreed. No new packages.
> - **`createNotificationInTx` writes the notification AND its `notification` outbox row** (AC: "the notification row and its outbox row commit atomically"). The plan's version wrote only the notification and left the pairing to each caller, so a caller could forget it. `appendOutboxInTx(tx, {topic, entityId})` is still exported for other owners (Plan in 7.8, check-offs in 7.10). `NOTIFICATION_TOPIC = "notification"` is exported.
> - **`deepLink` is `string | null` and required** (Ruling R11) in both `CreateNotificationInput` and the read-back `NotificationRecord`. The plan's optional `deepLink?` and its `...spread` omission would not type-check against the locked `api.ts`.
> - **Mark-read is also a user-visible change, so it appends a `notification` outbox hint** in the same `writeTx` (AD-18: "every user-visible change"). This lets other open tabs drop the badge. The store returns `{status: "marked" | "already-read", readAt} | {status: "not-found"}`. It is idempotent: a second mark keeps the first `readAt` and adds no hint. `app/notifications.ts` maps not-found to a `validation` error rather than reporting success.
> - **New wire shapes in `api.ts` (additive only):** `NotificationList`, `MarkNotificationReadRequest`, `MarkNotificationReadResponse {id, readAt}`. The app functions use them as their input and output (AD-16).
> - **`server.ts` kept 7.2's shape instead of the plan's rewrite.** It keeps the single chained app, the duration-logging middleware, `LOOPBACK_HOST`, port validation, and structured start/stop logs. `ServerDeps` gains a required `connection` plus optional `log`/`now`/`clock`/`eventStream`. The zero-arg `export const app` is gone, since the server can't exist without a connection. `AppType = ReturnType<typeof createApp>`. `startServer(connection, env, serveFn)` takes the connection that `main` opened; `main` owns it and closes it on shutdown. The plan's default-parameter `openSqliteConnection` inside `startServer` was dropped.
> - **Routes:** `GET /api/events`, `GET /api/notifications`, `POST /api/notifications/:id/read`. Every body is the serialized `Result`, with `detail` stripped before it crosses the wire. The HTTP status mirrors the error kind (`validation`/`missing-field` 400, `stale-proposal`/`conflict` 409, `rate-limited` 429, `unreachable`/`auth-expired` 503), so the logs and devtools show the real outcome.
> - **The SSE loop ends when the client disconnects.** Hono's `StreamingApi.write` swallows errors after the client goes away. The plan's loop would have spun forever, one leaked loop per closed tab. `runEventStream` checks `stream.aborted`, and its default sleep wakes early through `onAbort`. `SseStreamLike` gained `aborted` and `onAbort`. `sleep(ms, signal)` is injectable. The first tick runs immediately, which flushes headers through any proxy, so N ticks means N-1 sleeps; the plan's test expected N.
> - **`Last-Event-ID` hardening:** a malformed value (`abc`, `-1`, `1.5`, anything but 1-15 digits) starts fresh, at the current max seq. A value above the current max is clamped, so an id from a reset DB can't wedge the stream. The plan's `Number(...)` would have turned `abc` into `NaN`, and `seq > NaN` never matches.
> - **`KEEP_ALIVE_COMMENT = ": keep-alive\n\n"`** is exported. A stream error is logged as `server.event-stream-failed`; the client's EventSource reconnects with `Last-Event-ID` and loses nothing.
> - **Carry-in from the 7.2 review:** the duration middleware now uses `try/finally`. Hono's compose sends a thrown `Error` to `onError`, so `next()` resolves with a 500 and the line was already logged. A thrown non-`Error` value, though, is rethrown through `next()`, and that case skipped the log line. The test covers both cases, and the rethrow case logs status 500.
> - **`shell/ritual-cli.ts` main also calls `initNotificationStoreSchema(connection.db)`** ("any process may create notifications"), alongside `initCompletionLogSchema`. The server's main does the same. A source-scan test pins both.
> - **Guards:** source scans assert that only `notification-store.ts` has SQL against `notifications`/`outbox`, that `OUTBOX_POLL_INTERVAL_MS` is declared only there, and that `server.ts` imports no store write. `@ts-expect-error` checks reject `"check-in"`, `"progress"`, a widened `string` kind, and an omitted `deepLink`.
> - **Tests never wait on the real 2 s interval:** unit tests use a fake stream with an instant sleep. Route tests use `app.request` and one real loopback socket (port 0) with a 5 ms poll. Cleanup runs in `t.after`, so a regression fails the test instead of hanging the process. Mutation-checked: removing the keep-alive, either abort check, the `Last-Event-ID` plumbing, fresh-start-at-max, the clamp, or the `id:` field, adding data to a hint, or making the sleep non-abortable each turns the suite red.
> - **Live smoke (Mac, 2026-09-26, `YOH_SERVER_PORT=18788`):** a separate `node` process raised a notification on the shared file, and its hint arrived on an open `/api/events` stream about 1.5 s later, at the next poll tick. Reconnecting with `Last-Event-ID: 0` replayed it. The list, mark-read (200), and unknown-id mark-read (400) all returned the expected envelopes. On SIGTERM with a stream open, the server exits 0 after the 3 s grace. Not yet verified through `tailscale serve` (manual checklist below).

**Spec:** SDD plan Task 3 (`_bmad-output/implementation-artifacts/sdd-plan-YohV1-phase2.md`); `ARCHITECTURE-SPINE.md` AD-10 (dedicated tables, `...InTx` convention), AD-18 (the full live-delivery rule).

## Global Constraints

- `adapters/notification-store.ts` is the only file that reads or writes the `notifications`/`outbox` tables — every other caller goes through its exported functions (AD-10).
- A notification's `kind` must be a member of the closed `NotificationKind` union (`types/api.ts`, Story 7.2) — enforced at the type level, proved by a `@ts-expect-error` compile check.
- The notification row and its outbox row commit atomically, in the same `writeTx` (AD-18) — never two separate transactions.
- SSE (`GET /api/events`) carries hints only (`{seq, topic, entityId}`), never data. An SSE comment keep-alive goes out on every poll tick, so `tailscale serve` never sees an idle connection. On reconnect with `Last-Event-ID`, the server replays every hint after that `seq`.
- The outbox poll interval (`OUTBOX_POLL_INTERVAL_MS`, ~2 s) is exported exactly once, from `notification-store.ts` (Shared tuning constants convention) — no other file redeclares it.

```ts
/**
 * src/adapters/notification-store.ts
 *
 * Story 7.3, AD-10/AD-18: the sole owner of the `notifications` and
 * `outbox` tables — dedicated, idempotently-created tables (never
 * `memory-store.ts`'s generic `(kind, id)` blob table, per AD-10's Phase 2
 * revision). No other file reads or writes either table directly.
 *
 * Two low-level functions take the raw `better-sqlite3` handle a caller is
 * ALREADY inside a `writeTx` with — `createNotificationInTx`/
 * `appendOutboxInTx` — so a change spanning owners (Story 7.8's Plan write
 * plus its outbox hint, Story 7.10's check-off commit) can call both from
 * inside its own single `writeTx`, atomically, without this file needing to
 * know about the other owner's tables. `createNotification` is the
 * convenience wrapper for the common single-owner case (a cron ritual or
 * the server raising one notification on its own).
 */
import { randomUUID } from "node:crypto";
import type Database from "better-sqlite3";
import type { SqliteConnection } from "./sqlite.ts";
import type { NotificationKind, NotificationRecord } from "../types/api.ts";

/**
 * The outbox poll interval (AD-18, `[ASSUMPTION: ~2s]`) — the ONE defining
 * export for this shared tuning constant (Consistency Conventions). `GET
 * /api/events`'s `runEventStream` (Story 7.3, `shell/server.ts`) is this
 * value's one real caller; nothing else redeclares it.
 */
export const OUTBOX_POLL_INTERVAL_MS = 2000;

/** Idempotently creates both tables — safe to call every time a process starts, including against a file a previous run already initialized. */
export function initNotificationStoreSchema(db: Database.Database): void {
  db.exec(`
    CREATE TABLE IF NOT EXISTS notifications (
      id TEXT PRIMARY KEY,
      kind TEXT NOT NULL,
      title TEXT NOT NULL,
      body TEXT NOT NULL,
      deep_link TEXT,
      created_at TEXT NOT NULL,
      read_at TEXT
    );
    CREATE TABLE IF NOT EXISTS outbox (
      seq INTEGER PRIMARY KEY AUTOINCREMENT,
      topic TEXT NOT NULL,
      entity_id TEXT NOT NULL,
      created_at TEXT NOT NULL
    );
  `);
}

export interface CreateNotificationInput {
  readonly kind: NotificationKind;
  readonly title: string;
  readonly body: string;
  readonly deepLink?: string;
  readonly createdAt: string;
}

/**
 * Inserts one notification row, generating its id. Call ONLY from inside a
 * `writeTx` — pair it with `appendOutboxInTx` in the SAME transaction so
 * they commit atomically (AD-18). Returns the generated id so the caller
 * can use it as the paired outbox row's `entityId`.
 */
export function createNotificationInTx(db: Database.Database, input: CreateNotificationInput): string {
  const id = randomUUID();
  db.prepare(
    `INSERT INTO notifications (id, kind, title, body, deep_link, created_at)
     VALUES (@id, @kind, @title, @body, @deepLink, @createdAt)`,
  ).run({
    id,
    kind: input.kind,
    title: input.title,
    body: input.body,
    deepLink: input.deepLink ?? null,
    createdAt: input.createdAt,
  });
  return id;
}

export interface OutboxEntry {
  readonly topic: string;
  readonly entityId: string;
}

/**
 * Appends one outbox row `{seq (monotonic), topic, entityId}` — the ONE way
 * any owner signals a user-visible change (AD-18). Every caller spanning
 * owners threads its own `db` (from inside its own `writeTx`) through here
 * rather than touching the `outbox` table directly.
 */
export function appendOutboxInTx(db: Database.Database, entry: OutboxEntry): void {
  db.prepare(`INSERT INTO outbox (topic, entity_id, created_at) VALUES (@topic, @entityId, @createdAt)`).run({
    topic: entry.topic,
    entityId: entry.entityId,
    createdAt: new Date().toISOString(),
  });
}

/** Convenience wrapper for the common single-owner case: opens its own `writeTx`, creates the notification, and appends its outbox row, atomically. Returns the generated notification id. */
export function createNotification(connection: SqliteConnection, input: CreateNotificationInput): string {
  return connection.writeTx((db) => {
    const id = createNotificationInTx(db, input);
    appendOutboxInTx(db, { topic: "notification", entityId: id });
    return id;
  });
}

export interface OutboxRow {
  readonly seq: number;
  readonly topic: string;
  readonly entityId: string;
}

interface OutboxDbRow {
  readonly seq: number;
  readonly topic: string;
  readonly entity_id: string;
}

/** Every outbox row with `seq` strictly greater than `sinceSeq`, in `seq` order — what `GET /api/events`'s tail loop reads on every poll tick. */
export function tailOutboxSince(connection: SqliteConnection, sinceSeq: number): OutboxRow[] {
  const rows = connection.db
    .prepare<{ sinceSeq: number }, OutboxDbRow>(`SELECT seq, topic, entity_id FROM outbox WHERE seq > @sinceSeq ORDER BY seq`)
    .all({ sinceSeq });
  return rows.map((r) => ({ seq: r.seq, topic: r.topic, entityId: r.entity_id }));
}

/** The current highest outbox `seq`, or `0` if the outbox is empty — used to start a fresh (no-`Last-Event-ID`) SSE connection at "now," never replaying the whole history. */
export function getMaxOutboxSeq(connection: SqliteConnection): number {
  const row = connection.db.prepare(`SELECT COALESCE(MAX(seq), 0) AS maxSeq FROM outbox`).get() as { maxSeq: number };
  return row.maxSeq;
}

interface NotificationDbRow {
  readonly id: string;
  readonly kind: NotificationKind;
  readonly title: string;
  readonly body: string;
  readonly deep_link: string | null;
  readonly created_at: string;
  readonly read_at: string | null;
}

function rowToRecord(row: NotificationDbRow): NotificationRecord {
  return {
    id: row.id,
    kind: row.kind,
    title: row.title,
    body: row.body,
    ...(row.deep_link !== null ? { deepLink: row.deep_link } : {}),
    createdAt: row.created_at,
    ...(row.read_at !== null ? { readAt: row.read_at } : {}),
  };
}

/** Every notification with no `readAt` yet, oldest first — what `GET /api/notifications` returns. */
export function listUnreadNotifications(connection: SqliteConnection): NotificationRecord[] {
  const rows = connection.db
    .prepare<[], NotificationDbRow>(
      `SELECT id, kind, title, body, deep_link, created_at, read_at FROM notifications WHERE read_at IS NULL ORDER BY created_at`,
    )
    .all();
  return rows.map(rowToRecord);
}

/** Sets `readAt` on notification `id` — a harmless no-op if `id` doesn't exist (already resolved some other way) or is already read. */
export function markNotificationRead(connection: SqliteConnection, id: string, readAt: string): void {
  connection.db.prepare(`UPDATE notifications SET read_at = @readAt WHERE id = @id`).run({ id, readAt });
}
```

```ts
/**
 * src/app/notifications.ts
 *
 * Story 7.3's first real `app/` use-case file (AD-16): reading and
 * acknowledging in-app notifications. Both exports are shaped `(deps,
 * input) => Promise<Result<Output, YohError>>`, checked structurally by
 * `tests/layering-rules.test.ts` (Story 7.2).
 */
import type { SqliteConnection } from "../adapters/sqlite.ts";
import { listUnreadNotifications, markNotificationRead as storeMarkRead } from "../adapters/notification-store.ts";
import type { NotificationRecord } from "../types/api.ts";
import type { Result, YohError } from "../types/domain.ts";

export interface NotificationsDeps {
  readonly connection: SqliteConnection;
  readonly now: () => Date;
}

export async function listNotifications(
  deps: NotificationsDeps,
  _input: Record<string, never>,
): Promise<Result<{ notifications: readonly NotificationRecord[] }, YohError>> {
  try {
    return { ok: true, value: { notifications: listUnreadNotifications(deps.connection) } };
  } catch (err) {
    return {
      ok: false,
      error: {
        kind: "unreachable",
        message: `notifications: could not read notifications — ${err instanceof Error ? err.message : String(err)}`,
        detail: err,
      },
    };
  }
}

export interface MarkNotificationReadInput {
  readonly id: string;
}

export async function markNotificationRead(
  deps: NotificationsDeps,
  input: MarkNotificationReadInput,
): Promise<Result<{ readAt: string }, YohError>> {
  try {
    const readAt = deps.now().toISOString();
    storeMarkRead(deps.connection, input.id, readAt);
    return { ok: true, value: { readAt } };
  } catch (err) {
    return {
      ok: false,
      error: {
        kind: "unreachable",
        message: `notifications: could not mark ${input.id} read — ${err instanceof Error ? err.message : String(err)}`,
        detail: err,
      },
    };
  }
}
```

```ts
import { Hono } from "hono";
import { serve } from "@hono/node-server";
import { streamSSE } from "hono/streaming";
import { openSqliteConnection, type SqliteConnection } from "../adapters/sqlite.ts";
import { getMaxOutboxSeq, tailOutboxSince, OUTBOX_POLL_INTERVAL_MS } from "../adapters/notification-store.ts";
import { listNotifications, markNotificationRead } from "../app/notifications.ts";

export interface AppDeps {
  readonly connection: SqliteConnection;
}

/** The minimal SSE-stream surface `runEventStream` needs — satisfied by Hono's real `SSEStreamingApi` (`streamSSE`'s callback argument) and by a plain fake in tests. */
export interface SseStreamLike {
  writeSSE(message: { readonly data?: string; readonly event?: string; readonly id?: string }): Promise<void>;
  write(chunk: string): Promise<void>;
}

export interface RunEventStreamOptions {
  /** The `Last-Event-ID` request header, if the client is reconnecting. Absent means "start fresh, at the current max seq." */
  readonly lastEventId?: string;
  readonly pollIntervalMs?: number;
  /** Bounds the loop for tests. Defaults to unbounded (the real SSE connection lives until the client disconnects). */
  readonly maxTicks?: number;
  readonly sleep?: (ms: number) => Promise<void>;
}

const defaultSleep = (ms: number): Promise<void> => new Promise((resolve) => setTimeout(resolve, ms));

/**
 * The tail/replay/keep-alive loop behind `GET /api/events` (AD-18): on
 * every poll tick, sends one SSE hint per outbox row past `sinceSeq`
 * (starting from `lastEventId` on reconnect, or the current max seq on a
 * fresh connection — never replaying the whole history to a first-time
 * client), then one SSE comment keep-alive. Runs `maxTicks` times (default:
 * forever, until the real connection drops) — a test bounds it and injects
 * a zero-delay `sleep` so the suite never waits on a real interval.
 */
export async function runEventStream(
  stream: SseStreamLike,
  connection: SqliteConnection,
  options: RunEventStreamOptions = {},
): Promise<void> {
  const pollIntervalMs = options.pollIntervalMs ?? OUTBOX_POLL_INTERVAL_MS;
  const sleep = options.sleep ?? defaultSleep;
  const maxTicks = options.maxTicks ?? Number.POSITIVE_INFINITY;

  let sinceSeq = options.lastEventId !== undefined ? Number(options.lastEventId) : getMaxOutboxSeq(connection);

  for (let tick = 0; tick < maxTicks; tick++) {
    const hints = tailOutboxSince(connection, sinceSeq);
    for (const hint of hints) {
      await stream.writeSSE({ data: JSON.stringify({ seq: hint.seq, topic: hint.topic, entityId: hint.entityId }), id: String(hint.seq) });
      sinceSeq = hint.seq;
    }
    await stream.write(": keep-alive\n\n");
    if (tick < maxTicks - 1) await sleep(pollIntervalMs);
  }
}

export function createApp(deps: AppDeps) {
  const app = new Hono()
    .get("/api/health", (c) => c.json({ ok: true } as const))
    .get("/api/events", (c) =>
      streamSSE(c, async (stream) => {
        await runEventStream(stream, deps.connection, { lastEventId: c.req.header("Last-Event-ID") });
      }),
    )
    .get("/api/notifications", async (c) => {
      const result = await listNotifications({ connection: deps.connection, now: () => new Date() }, {});
      return c.json(result);
    })
    .post("/api/notifications/:id/read", async (c) => {
      const result = await markNotificationRead({ connection: deps.connection, now: () => new Date() }, { id: c.req.param("id") });
      return c.json(result);
    });
  return app;
}

export type AppType = ReturnType<typeof createApp>;

const DEFAULT_PORT = 8787;

export interface ServerHandle {
  close(): void;
}

type ServeFn = (options: { fetch: (request: Request) => Response | Promise<Response>; hostname: string; port: number }) => { close(): void };

/**
 * Starts the server, bound to loopback only (AD-15). `serveFn` defaults to
 * the real `@hono/node-server` `serve`; a test injects a fake instead. If
 * no `connection` is supplied, opens one from `MEMORY_DB_PATH` (or its
 * default) — the process's own one-connection-per-process handle (AD-10),
 * closed alongside the HTTP listener on shutdown.
 */
export function startServer(
  env: Readonly<Record<string, string | undefined>> = process.env,
  serveFn: ServeFn = serve as unknown as ServeFn,
  connection: SqliteConnection = openSqliteConnection({ databasePath: env["MEMORY_DB_PATH"] || "./data/yoh-memory.db" }),
): ServerHandle {
  const port = Number(env["YOH_SERVER_PORT"] ?? DEFAULT_PORT);
  const app = createApp({ connection });
  const httpHandle = serveFn({ fetch: app.fetch, hostname: "127.0.0.1", port });
  return {
    close(): void {
      httpHandle.close();
      connection.close();
    },
  };
}

if (import.meta.main) {
  const connection = openSqliteConnection({ databasePath: process.env["MEMORY_DB_PATH"] || "./data/yoh-memory.db" });
  const { initNotificationStoreSchema } = await import("../adapters/notification-store.ts");
  initNotificationStoreSchema(connection.db);
  const handle = startServer(process.env, serve as unknown as ServeFn, connection);
  process.stdout.write(`yoh-server: listening on 127.0.0.1:${process.env["YOH_SERVER_PORT"] ?? DEFAULT_PORT}\n`);
  process.on("SIGTERM", () => handle.close());
}
```
