# Story 9.3 — /sandbox Finale and Proof-of-Action Notification — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a `/sandbox` session reaches the end of its (exclude-adjusted) queue — the last card saved or skipped — Spencer sees proof that his answers actually landed in Notion, without a click. A right-aligned `accent-solid` loading bar (the Sandbox Finale) appears in the chat stream while `app/sandbox-submit.ts`'s `finishSandboxSession` settles every card write from this session's accumulated outcome list, then resolves to either "Saved {n} Tasks" (every write succeeded) or a named list of what failed (`"Couldn't save Chem problem set."` — one line per failure, never both a success and a failure claim in the same message). The identical outcome also raises exactly one `sandbox-complete` or `sandbox-failed` in-app notification, deep-linking to Chat (`"chat"`, or `"chat:/sandbox"` to re-open the queue for a retry) — the first real `deepLink` this codebase has ever set. A short, generated (no external asset) reward chime plays once, only when the session saved at least one card and reduced motion is off. An all-skip session (zero saves, however many skips) ends quietly instead — no Finale, no server round trip, no notification (controller ruling, ambiguity resolved below) — since "Saved 0 Tasks" is never a sentence Spencer should see.

**Architecture:** `finishSandboxSession` (extends Task 2's `src/app/sandbox-submit.ts`) is pure transport-adjacent glue: it takes the client's own accumulated `SandboxSessionOutcome[]` (already-settled writes — Task 2's `submitSandboxCard` writes synchronously per card, so by the time this function runs nothing is still in flight) and raises **at most one** notification via `createNotificationInTx`, inside one `writeTx`, using the same `MemoryStore`/`SqliteConnection` seam `app/check-off.ts`'s own `operational` notification already uses. `POST /api/sandbox/finish` is one more `wire`/`httpStatus` route on the same optional `deps.sandbox` bucket Task 2 introduced to `ServerDeps` — absent, it reports the same "not configured" envelope every other Notion-backed route does. Client-side, `web/src/lib/sandbox.ts`'s `finishSandbox()` (extends Task 2's file) is the one new integration seam: the moment `saveCard`/`skipCard` (Task 2) receive a `next: undefined` response (queue now empty), they call `finishSandbox()` automatically instead of leaving the session idle — never a separate click (FR-38). `finishSandbox()` renders the Finale as one more entry in the same `StreamEntry` list `chatStore.ts` already threads through the chat transcript (Task 2 adds `"message"`/`"sandbox-card"` kinds; this story adds a third, `"sandbox-finale"`), holding the loading bar up for a small named minimum duration so a near-instant response never flashes illegibly, then finalizing it and — only if `savedCount >= 1` — calling `sandboxSound.ts`'s one exported `playSandboxCompleteChime()` (an oscillator envelope via the Web Audio API, no file to load, silent under reduced motion, gated **inside** that one function so every call site stays unconditional). `NotificationOverlay.tsx`'s `activate()` gains the one new branch this epic needs everywhere a "deep-link to Chat" appears: a `deepLink` starting with `"chat"` calls a new shared helper, `web/src/lib/chatPanel.ts`'s `openChatWithCommand(command?)`, instead of `resolveDeepLinkIndex`/`nav.goTo` — every existing page-id deep link (none in production use yet) is untouched.

**Tech Stack:** `node:test` with a real `:memory:` SQLite connection and `notification-store.ts`'s own `listUnreadNotifications` (existing convention — no fakes needed, this story writes no Notion call of its own). Vitest + RTL for the four `web/` units (`SandboxFinale.tsx`, `sandboxSound.ts`, `chatPanel.ts`'s new export, `NotificationOverlay.tsx`'s extension, `useReducedMotion.ts`'s new plain export) — a hand-rolled fake `AudioContext`/`OscillatorNode`/`GainNode` (`vi.stubGlobal`, the same convention `web/src/test/setup.ts` already uses for `EventSource`) stands in for jsdom's total absence of Web Audio. Playwright extends Task 2's own `web/e2e/sandbox.spec.ts` (assumed; see below) with one more full-session spec against `tests/e2e/fixture-server.ts`.

**Spec:** `_bmad-output/planning-artifacts/architecture/architecture-YohV1-2026-08-22/ARCHITECTURE-SPINE.md` AD-1, AD-5, AD-10, AD-11, AD-16, AD-17, AD-18; `_bmad-output/planning-artifacts/epics.md` Story 9.3, UX-DR39 (OQ10, OQ16); `_bmad-output/implementation-artifacts/sdd-plan-YohV1-phase2-epic9.md` Task 3 (Epic 9 Interface Contract E6, E8, E10; controller rulings 1–3, 6).

## Global Constraints

The subset binding this story (full text: SDD plan's "Global Constraints" section):

- **`app/` layer (AD-16):** `finishSandboxSession` is `(deps, input) => Promise<Result<Output, YohError>>`, exported from `app/sandbox-submit.ts` alongside Task 2's `submitSandboxCard` — same file, same shape.
- **Storage (AD-10, AD-18):** `adapters/sqlite.ts`'s `writeTx` is the only way to write; every user-visible change (here: one notification) appends one outbox row in the same transaction, via `createNotificationInTx` — never a bespoke insert.
- **Live delivery (AD-18):** the web client never opens a second `EventSource`; the notification reaches an open tab through the existing shared `eventBus.ts`/`notifications.ts` pipeline (Story 7.3/7.7), unchanged by this story.
- **Browser client (AD-17):** the Finale's `savedCount`/`failedTitles` are exactly what the server returned — no client-side recomputation of "how many saved."
- **Web UI (FR-46, NFR-Accessibility):** the loading bar and its resolved text use only `web/src/tokens.css` tokens; the shimmer reads `useReducedMotion.ts` and drops to a static fallback; the failed-Task list is never color-only (it's plain sentences, one per line).
- **Tone (FR-18, FR-19, FR-42):** "Saved {n} Tasks" / "Couldn't save {Task}." — peer-level, no filler, no exclamation points, no internal field names.
- **Tests:** `node:test` for `src/`, Vitest + RTL for `web/`, Playwright smoke for `web/`. Gate: `npm run check` plus `cd web && npx playwright test`. Baseline at this plan's dispatch is whatever Tasks 1–2 leave the suite at (this plan does not restate their counts); this story's own gate step re-reads the counts freshly before asserting its own additions landed.
- **Epic 9 specifics:** sandbox writes are direct writes, no `Proposal`, no confirm step (unaffected — this story raises a notification, not a write). `finishSandboxSession` raises **at most one** of `sandbox-complete`/`sandbox-failed`, never both (E6). `needs-data` and `operational` are the only kinds a *ritual* may raise (Task 4's concern, not this one) — `sandbox-complete`/`sandbox-failed` are raised by `app/`, which this story is.
- **Deep-link convention (E8, this story defines it):** `"chat"` opens the panel only; `"chat:/sandbox"` opens the panel and sends `/sandbox` as if typed. One shared helper, `openChatWithCommand(command?)`, in `web/src/lib/chatPanel.ts`.

## Review Focus

Five failure modes the ACs imply but no single moved/existing test already exercises — each gets its own pinning test in the step named:

1. **A session with a mix of successes and failures must raise `sandbox-failed`, never `sandbox-complete`, and must never claim completion for the failed Tasks.** The AC only separately states the all-success and any-failure cases; the *mixed* case (2 saved, 1 failed) is the one most likely to regress toward "reports whichever kind came first" or "counts a failure as saved." Pinned in Task 1, Step 1 (`finishSandboxSession` mixed-outcome test).
2. **`finishSandboxSession` must never be reachable with an empty `outcomes` array in a way that raises "Saved 0 Tasks."** Ruling (a) puts this gate entirely client-side (an all-skip session never calls the route at all) — but `finishSandboxSession` itself is a public `app/` export reachable directly (a test, a future caller, a replayed request). Defense in depth: called with `outcomes: []`, it must return `{savedCount: 0, failedTitles: []}` and raise **no** notification at all. Pinned in Task 1, Step 1.
3. **The Finale's minimum-duration hold must not double-count or hang if the server responds instantly** (a `:memory:`-backed fixture server typically does). A naive `await sleep(MIN_DURATION_MS)` *after* the response, unconditionally, would make even a slow response feel doubly slow; the correct shape waits only for the *remaining* time. Pinned in Task 8, Step 1 (`finishSandbox` timing test with an injectable clock).
4. **A `deepLink` of exactly `"chat"` must never also send a command** (only `"chat:/sandbox"` does), and an unrecognized `deepLink` that merely *starts with* `"chat"` in some other shape (defensive, in case a future kind reuses the prefix carelessly) must not crash `activate()`. Pinned in Task 7, Step 1 (`NotificationOverlay` deep-link tests) and Task 6, Step 1 (`openChatWithCommand` unit tests).
5. **The reward chime must never throw when `AudioContext` is unavailable or a browser refuses to construct one** (a real production risk — Safari's autoplay/user-gesture policies, or an environment with Web Audio disabled) — `playSandboxCompleteChime()` is called from a session-ending code path that must complete regardless. Pinned in Task 5, Step 1 (`sandboxSound.test.ts`, an `AudioContext` constructor that throws).

 * Story 9.3, E6: the Finale's one server round trip. Every card write in
 * `outcomes` already completed (success or failure) synchronously before
 * the client advanced past it (Task 2's `submitSandboxCard`) — nothing is
 * actually still in flight here. Raises AT MOST ONE of `sandbox-complete`
 * (every outcome ok:true) or `sandbox-failed` (any outcome ok:false, each
 * failed Task named) — never both, and never when `outcomes` is empty
 * (ruling: the client never calls this for an all-skip session; this is
 * the defensive floor if it ever does).
 */
export interface SandboxSessionOutcome {
  readonly taskId: string;
  readonly taskTitle: string;
  /** true = this card's write succeeded this session; a skipped card never appears here. */
  readonly ok: boolean;
}
export interface SandboxFinishInput {
  readonly outcomes: readonly SandboxSessionOutcome[];
}
export interface SandboxFinishOutput {
  readonly savedCount: number;
  readonly failedTitles: readonly string[];
}

function sandboxCompleteBody(savedCount: number): string {
  return `Saved ${savedCount} Tasks`;
}

function sandboxFailedBody(failedTitles: readonly string[]): string {
  return failedTitles.length === 1 ? `Couldn't save ${failedTitles[0]}.` : `Couldn't save: ${failedTitles.join(", ")}.`;
}

export async function finishSandboxSession(deps: SandboxSubmitDeps, input: SandboxFinishInput): Promise<Result<SandboxFinishOutput, YohError>> {
  const outcomes = Array.isArray(input.outcomes) ? input.outcomes : [];
  const savedCount = outcomes.filter((o) => o.ok).length;
  const failedTitles = outcomes.filter((o) => !o.ok).map((o) => o.taskTitle);

  if (outcomes.length === 0) {
    return { ok: true, value: { savedCount: 0, failedTitles: [] } };
  }

  const createdAt = deps.now().toISOString();
  deps.connection.writeTx((db) => {
    if (failedTitles.length === 0) {
      createNotificationInTx(db, { kind: "sandbox-complete", title: sandboxCompleteBody(savedCount), body: sandboxCompleteBody(savedCount), deepLink: "chat", createdAt });
    } else {
      const body = sandboxFailedBody(failedTitles);
      createNotificationInTx(db, { kind: "sandbox-failed", title: body, body, deepLink: "chat:/sandbox", createdAt });
    }
  });

  return { ok: true, value: { savedCount, failedTitles } };
}

import { useEffect, useState } from "react";

const QUERY = "(prefers-reduced-motion: reduce)";

/** The plain, non-hook read — the one `matchMedia` call site every caller (hook or not) goes through. */
export function prefersReducedMotion(): boolean {
  return window.matchMedia(QUERY).matches;
}

export function useReducedMotion(): boolean {
  const [reduced, setReduced] = useState(prefersReducedMotion);

  useEffect(() => {
    const mql = window.matchMedia(QUERY);
    const onChange = (): void => setReduced(mql.matches);
    mql.addEventListener("change", onChange);
    return () => mql.removeEventListener("change", onChange);
  }, []);

  return reduced;
}

/**
 * web/src/lib/sandboxSound.ts
 *
 * Story 9.3, UX-DR39/OQ16 (rulings (b)/(c)): the ONE reward-chime call
 * site (`playSandboxCompleteChime`) — an oscillator envelope, no external
 * asset, swappable here without touching any caller. Reduced motion is
 * checked INSIDE this function (not by the caller, `sandbox.ts`, which is
 * plain client state, not a component). Never throws: a browser refusing
 * to construct an `AudioContext` must not interrupt the session-ending
 * path that calls this.
 */
import { prefersReducedMotion } from "../hooks/useReducedMotion.ts";

const CHIME_FREQUENCY_HZ = 880; // A5
const CHIME_DURATION_SECONDS = 0.22;
const CHIME_PEAK_GAIN = 0.12; // modest volume, per ruling (b)

export function playSandboxCompleteChime(): void {
  if (prefersReducedMotion()) return;
  try {
    const Ctor = (globalThis as { AudioContext?: typeof AudioContext }).AudioContext;
    if (!Ctor) return;
    const ctx = new Ctor();
    const oscillator = ctx.createOscillator();
    const gain = ctx.createGain();
    oscillator.type = "sine";
    oscillator.frequency.value = CHIME_FREQUENCY_HZ;
    gain.gain.setValueAtTime(0, ctx.currentTime);
    gain.gain.linearRampToValueAtTime(CHIME_PEAK_GAIN, ctx.currentTime + 0.02);
    gain.gain.exponentialRampToValueAtTime(0.0001, ctx.currentTime + CHIME_DURATION_SECONDS);
    oscillator.connect(gain).connect(ctx.destination);
    oscillator.start();
    oscillator.stop(ctx.currentTime + CHIME_DURATION_SECONDS + 0.02);
    oscillator.onended = () => ctx.close();
  } catch {
    // Never the only confirmation, and never load-bearing — a construction
    // or playback failure (no user gesture yet, Web Audio disabled) is a
    // silent no-op, not a broken session end.
  }
}

```ts
import { appendStreamEntry, updateStreamEntry } from "./chatStore.ts";
import { requestSandboxFinish } from "./sandboxClient.ts";
import { playSandboxCompleteChime } from "./sandboxSound.ts";

/**
 * Story 9.3: how long the Finale's loading bar stays up at minimum, so a
 * near-instant response (the common case — every card write already
 * settled before the client advanced past it, Task 2) never flashes
 * illegibly. Waits only for whatever time REMAINS after the request
 * settles, never a flat delay stacked on top of an already-slow response.
 */
export const SANDBOX_FINALE_MIN_DURATION_MS = 500;

function sleep(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

/**
 * Called automatically the instant the (exclude-adjusted) queue empties —
 * `saveCard`/`skipCard`'s own tail below, never a separate click (FR-38).
 * Ruling (a): a session that saved NOTHING this round (zero outcomes,
 * however many cards were skipped) ends quietly — no Finale, no server
 * call, no notification, no chime — since "Saved 0 Tasks" is never a
 * sentence Spencer should see.
 */
export async function finishSandbox(): Promise<void> {
  const outcomes = state.outcomes;
  if (outcomes.length === 0) {
    appendStreamEntry({ kind: "message", turn: { role: "assistant", content: "Nothing more to place this round." } });
    resetSandboxSession();
    return;
  }

  const entryId = appendStreamEntry({ kind: "sandbox-finale", status: "pending" });
  const startedAt = Date.now();
  const result = await requestSandboxFinish(outcomes);
  const elapsed = Date.now() - startedAt;
  if (elapsed < SANDBOX_FINALE_MIN_DURATION_MS) await sleep(SANDBOX_FINALE_MIN_DURATION_MS - elapsed);

  if (result.ok) {
    updateStreamEntry(entryId, { status: "done", savedCount: result.value.savedCount, failedTitles: result.value.failedTitles });
    if (result.value.savedCount >= 1) playSandboxCompleteChime();
  } else {
    updateStreamEntry(entryId, { status: "done", savedCount: 0, failedTitles: outcomes.filter((o) => !o.ok).map((o) => o.taskTitle) });
  }
  resetSandboxSession();
}
```

/**
 * web/src/components/SandboxFinale.tsx
 *
 * Story 9.3, UX-DR39: one `sandbox-finale` `StreamEntry` in the chat
 * stream — a right-aligned `accent-solid` loading bar while
 * `POST /api/sandbox/finish` is in flight, then the resolved outcome.
 * `sandbox.ts`'s `finishSandbox()` owns WHEN this renders; this component
 * only renders whatever state it's given.
 */
import { useReducedMotion } from "../hooks/useReducedMotion.ts";

export interface SandboxFinaleProps {
  readonly status: "pending" | "done";
  readonly savedCount?: number;
  readonly failedTitles?: readonly string[];
}

export function SandboxFinale({ status, savedCount = 0, failedTitles = [] }: SandboxFinaleProps): React.JSX.Element {
  const reducedMotion = useReducedMotion();

  if (status === "pending") {
    return (
      <div className="flex justify-end py-1">
        <div data-testid="sandbox-finale-bar" role="status" aria-live="polite" aria-label="Saving your answers" className="w-32 overflow-hidden rounded-full bg-surface-sunken">
          <div className={"h-1.5 w-full rounded-full bg-accent-solid" + (reducedMotion ? "" : " sandbox-finale-shimmer")} />
        </div>
      </div>
    );
  }

  const failed = failedTitles.length > 0;
  return (
    <div data-testid="sandbox-finale-result" className="flex flex-col gap-0.5 py-1 text-body text-ink-primary">
      {failed ? failedTitles.map((title) => <p key={title}>{`Couldn't save ${title}.`}</p>) : <p>{`Saved ${savedCount} Tasks`}</p>}
    </div>
  );
}
