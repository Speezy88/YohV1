# Story 7.2: Web Server Reachable Only From My Devices — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lock `types/api.ts` (the browser-server wire contract) first, per AD-9. Scaffold the `app/` interaction layer and enforce its layering rules with a source-scan test. Stand up `shell/server.ts` (Hono + `@hono/node-server`), loopback-only, with `GET /api/health`. Document systemd + `tailscale serve` deployment so the server can actually run on Spencer's always-on host, reachable only from his own devices.

**Architecture:** `types/api.ts` carries the serialized `Result` envelope, the `{seq, topic, entityId}` event-hint shape, the notification record shape, and the closed `NotificationKind` union (AD-9, AD-18) — plus one type-only re-export of `shell/server.ts`'s Hono route type (`AppType`), so Story 7.5's browser client can get a compiler-checked `hono/client` RPC client while importing only from `types/` (AD-17). `shell/server.ts` exports a plain `Hono` app (`app`) built by `createApp()`, and a `startServer(env, serveFn?)` that binds `@hono/node-server`'s `serve()` to `127.0.0.1` only — `serveFn` is injectable so tests assert the bind arguments without opening a real socket, the same dependency-injection convention every other adapter in this codebase uses (`notification-adapter.ts`'s `FetchLike`). `src/app/` is scaffolded empty (a `.gitkeep`, matching `core/`/`rituals/`/`adapters/`/`shell/`'s existing convention) — Task 3 onward add real use-case files to it. A new `tests/layering-rules.test.ts` enforces AD-1/AD-16's two rules structurally: no file in `rituals/` or `shell/ritual-cli.ts` imports from `app/`, and no `shell/*.ts` file other than the named-allowlisted `chat-cli.ts` (Ruling R1 — deleted at Epic 8/FR-50 when `chat-cli.ts` itself is deleted) calls one of the four enumerated Notion/Calendar write functions directly.

**Tech Stack:** Hono ^4.13.9 + `@hono/node-server` ^4.13.9 (pinned per the Architecture Spine's Stack table), `node:test`.

**Spec:** SDD plan Task 2 (`_bmad-output/implementation-artifacts/sdd-plan-YohV1-phase2.md`, including its Implementer notes/Rulings R1/R2); `ARCHITECTURE-SPINE.md` AD-1 (Phase 2 revision), AD-9 (Phase 2 revision), AD-15, AD-16, AD-18 (for the shapes `api.ts` pins).

## Global Constraints

- `types/api.ts` is authored and reviewed *before* any `app/`, `shell/server.ts`, or `web/` file that uses it (AD-9). Later stories may add new shapes to it but never redeclare or widen one already exported.
- `shell/server.ts` listens on `127.0.0.1` only — never `0.0.0.0` or an unspecified host — and schedules no ritual (AD-15). The four cron one-shots stay OS-scheduled and unchanged.
- `shell/ritual-cli.ts` and everything in `rituals/` never imports from `app/` (AD-1). A shell file never calls `setTaskStatus`/`updateTaskField`/`createPage`/`applyCalendarEdit` directly, except `chat-cli.ts`'s existing Phase 1 call sites, named in an explicit allowlist the import-rule test reads (Ruling R1) — this exemption is recorded in `deferred-work.md` and is deleted when `chat-cli.ts` is deleted (FR-50/Epic 8).
- `app/` functions are shaped `(deps, input) => Promise<Result<Output, YohError>>` (AD-16) — no real use-case file is built in this story, but the scaffold and its test exist so Task 3 onward are checked automatically.
- Reachability is exclusively via `tailscale serve` HTTPS on the MagicDNS name — never Funnel, port-forward, or a public domain (AD-15). Tailnet membership is the only authentication; no login screen, session cookie, or password.

```ts
/**
 * src/types/api.ts
 *
 * The locked browser-server wire contract (AD-9, AD-17, AD-18), authored
 * and reviewed before any `app/`, `shell/server.ts`, or `web/` file that
 * uses it. No file may locally redeclare, widen, or shadow a shape this
 * file exports — extend this file instead. Later stories add new shapes
 * here (e.g. request/response DTOs for a specific route, `ChatMessage`) but
 * never touch what's already exported.
 *
 * `domain.ts` stays the home for shared business shapes (`YohError`,
 * `Plan`, `Task`, ...); this file is specifically the SERIALIZED wire shape
 * of the API surface — the two are related (every `ApiResult<T>` failure
 * carries a `YohError`) but distinct homes, per AD-9's Phase 2 revision.
 */
import type { YohError } from "./domain.ts";

// ============================================================================
// Serialized Result envelope
// ============================================================================

/**
 * The wire shape of `Result<T, YohError>` (`domain.ts`) after JSON
 * serialization. Every `/api/*` route (except the trivial liveness probe,
 * `GET /api/health`) returns exactly this shape — Consistency Conventions'
 * "JSON in and out, returning `{ok: true, value} | {ok: false, error}`."
 */
export type ApiResult<T> = { readonly ok: true; readonly value: T } | { readonly ok: false; readonly error: YohError };

// ============================================================================
// Live delivery — event hint (AD-18)
// ============================================================================

/**
 * One outbox hint delivered over `GET /api/events`'s SSE stream (Story
 * 7.3). SSE carries hints, never data — on receipt, the client re-fetches
 * through the ordinary API. `seq` is the outbox's own monotonic sequence
 * number, used as the SSE event id for `Last-Event-ID` replay on reconnect.
 */
export interface EventHint {
  readonly seq: number;
  readonly topic: string;
  readonly entityId: string;
}

// ============================================================================
// Notifications (AD-18, FR-49)
// ============================================================================

/**
 * The closed set of in-app notification kinds (AD-18). FR-49's "never a
 * proactive check-in" is enforced by this union being CLOSED — a progress
 * or check-in kind is not a constructible value, not merely a convention a
 * caller has to remember.
 */
export type NotificationKind =
  | "research-ready"
  | "research-failed"
  | "sandbox-complete"
  | "sandbox-failed"
  | "needs-data"
  | "reshuffle-apply-failed"
  | "operational";

/**
 * A durable in-app notification record — `notification-store.ts` (Story
 * 7.3) is the only file that ever constructs/writes one; this is its
 * wire/read shape, returned by `GET /api/notifications`.
 */
export interface NotificationRecord {
  readonly id: string;
  readonly kind: NotificationKind;
  readonly title: string;
  readonly body: string;
  /** Present only for a notification that navigates somewhere on click (AD-18); an `operational` notification never has one. */
  readonly deepLink?: string;
  readonly createdAt: string;
  readonly readAt?: string;
}
```

```ts
/**
 * Structural layering enforcement for Phase 2 (Story 7.2, AD-1/AD-16).
 * Mirrors the existing source-scan convention `tests/mid-day-reflow.test.ts`
 * and `tests/token-store.test.ts` already use for their own single-caller /
 * sole-importer rules.
 */
import { test } from "node:test";
import assert from "node:assert/strict";
import { readdirSync, readFileSync, statSync } from "node:fs";
import { join } from "node:path";

const SRC_DIR = join(import.meta.dirname, "..", "src");

function walk(dir: string, onFile: (fullPath: string) => void): void {
  for (const entry of readdirSync(dir)) {
    const full = join(dir, entry);
    const st = statSync(full);
    if (st.isDirectory()) {
      walk(full, onFile);
      continue;
    }
    if (full.endsWith(".ts")) onFile(full);
  }
}

test("AD-1: rituals/ and shell/ritual-cli.ts never import from app/", () => {
  const offenders: string[] = [];
  walk(SRC_DIR, (full) => {
    const isRitual = full.includes(`${join("src", "rituals")}${"/"}`) || full.endsWith(join("src", "shell", "ritual-cli.ts"));
    if (!isRitual) return;
    const contents = readFileSync(full, "utf8");
    if (/from\s+["'].*\/app\//.test(contents)) offenders.push(full);
  });
  assert.deepEqual(offenders, [], "rituals/ and shell/ritual-cli.ts must never import from app/ — the interactive layer is unreachable from a cron one-shot");
});

/**
 * AD-16's closed Notion/Calendar write surface. `chat-cli.ts` is the one
 * named exception (Ruling R1, SDD plan Task 2 notes): it still calls these
 * directly (Phase 1 logic Epic 8 moves into `app/`) — recorded in
 * `deferred-work.md`, and this allowlist entry is deleted along with
 * `chat-cli.ts` itself at FR-50/Epic 8.
 */
const ADAPTER_WRITE_FUNCTIONS = ["setTaskStatus", "updateTaskField", "createPage", "applyCalendarEdit"];
const SHELL_WRITE_ALLOWLIST = new Set(["chat-cli.ts"]);

test("AD-16: no shell/*.ts file other than the allowlisted chat-cli.ts calls a Notion/Calendar write function directly", () => {
  const shellDir = join(SRC_DIR, "shell");
  const offenders: string[] = [];
  for (const entry of readdirSync(shellDir)) {
    if (!entry.endsWith(".ts") || SHELL_WRITE_ALLOWLIST.has(entry)) continue;
    const contents = readFileSync(join(shellDir, entry), "utf8");
    for (const fn of ADAPTER_WRITE_FUNCTIONS) {
      if (new RegExp(`\\b${fn}\\b`).test(contents)) offenders.push(`${entry}: ${fn}`);
    }
  }
  assert.deepEqual(offenders, [], "only app/ may call setTaskStatus/updateTaskField/createPage/applyCalendarEdit (AD-16) — chat-cli.ts is the one recorded exception");
});

test("AD-16: every app/*.ts export shaped as an interaction use-case returns Promise<Result<...>>", () => {
  const appDir = join(SRC_DIR, "app");
  const offenders: string[] = [];
  for (const entry of readdirSync(appDir)) {
    if (!entry.endsWith(".ts")) continue; // skips .gitkeep
    const contents = readFileSync(join(appDir, entry), "utf8");
    const exportedFns = [...contents.matchAll(/export\s+(?:async\s+)?function\s+\w+\s*\([^)]*\)\s*:\s*([^\{]+)\{/g)];
    for (const match of exportedFns) {
      if (!/Promise<\s*Result</.test(match[1] ?? "")) offenders.push(`${entry}: ${match[0].slice(0, 60)}`);
    }
  }
  assert.deepEqual(offenders, [], "every app/*.ts exported function must be shaped (deps, input) => Promise<Result<Output, YohError>> (AD-16)");
});

test("AD-9: only types/api.ts may import from shell/, and only as a type-only re-export", () => {
  const typesDir = join(SRC_DIR, "types");
  const offenders: string[] = [];
  for (const entry of readdirSync(typesDir)) {
    if (!entry.endsWith(".ts")) continue;
    const contents = readFileSync(join(typesDir, entry), "utf8");
    const shellImports = [...contents.matchAll(/import\s+(type\s+)?\{[^}]*\}\s+from\s+["'][^"']*\/shell\/[^"']*["']/g)];
    for (const m of shellImports) {
      const isTypeOnly = m[1] !== undefined;
      if (entry !== "api.ts" || !isTypeOnly) offenders.push(`${entry}: ${m[0]}`);
    }
  }
  assert.deepEqual(offenders, [], "only types/api.ts may import from shell/, and only via `import type` (AD-17's RPC-client exception)");
});
```

```ts
/**
 * src/shell/server.ts
 *
 * Story 7.2, AD-15: the long-running, systemd-supervised server process.
 * Listens on loopback ONLY — reachable exclusively via `tailscale serve`
 * HTTPS on the MagicDNS name (see `deploy/DEPLOY.md`). Tailnet membership is
 * the authentication; there is no login screen, session cookie, or
 * password. Schedules no ritual — the four cron one-shots
 * (`morning`/`night-prompt`/`night-escalate`/`self-check`) stay
 * OS-scheduled and unchanged, driven by `shell/ritual-cli.ts`.
 *
 * `app` is exported as a plain `Hono` instance (not wrapped) so later
 * stories (7.3 onward) can call `.get()`/`.post()` on it directly to add
 * routes, and so `tests/server.test.ts`-style tests can drive it via
 * `app.request(...)` with no real socket. `AppType` is re-exported
 * type-only from `types/api.ts` (Ruling R2, AD-9/AD-17) so `web/`'s typed
 * Hono RPC client (Story 7.5) can import it while importing only `import
 * type` from `types/`.
 *
 * `startServer`'s `serveFn` parameter is injectable, mirroring every other
 * adapter's DI seam in this codebase (`notification-adapter.ts`'s
 * `FetchLike`) — this is what lets `tests/server.test.ts` assert the exact
 * bind arguments (`hostname: "127.0.0.1"`) without opening a real port.
 */
import { Hono } from "hono";
import { serve } from "@hono/node-server";

export function createApp(): Hono {
  const app = new Hono();
  app.get("/api/health", (c) => c.json({ ok: true } as const));
  return app;
}

export const app = createApp();

/** The Hono route type — imported type-only by `types/api.ts`'s `AppType` re-export (Ruling R2) for `web/`'s typed RPC client (Story 7.5, AD-17). */
export type AppType = typeof app;

const DEFAULT_PORT = 8787;

export interface ServerHandle {
  close(): void;
}

type ServeFn = (options: { fetch: typeof app.fetch; hostname: string; port: number }) => ServerHandle;

/**
 * Starts the server, bound to loopback only (AD-15). `serveFn` defaults to
 * the real `@hono/node-server` `serve`; a test injects a fake instead so no
 * real socket is ever opened in the test suite.
 */
export function startServer(
  env: Readonly<Record<string, string | undefined>> = process.env,
  serveFn: ServeFn = serve as unknown as ServeFn,
): ServerHandle {
  const port = Number(env["YOH_SERVER_PORT"] ?? DEFAULT_PORT);
  return serveFn({ fetch: app.fetch, hostname: "127.0.0.1", port });
}

if (import.meta.main) {
  const handle = startServer();
  process.stdout.write(`yoh-server: listening on 127.0.0.1:${process.env["YOH_SERVER_PORT"] ?? DEFAULT_PORT}\n`);
  // AD-15: this process is systemd-supervised (Restart=always) — a clean
  // shutdown on SIGTERM lets systemd's own restart/stop semantics work as
  // expected rather than relying on a hard kill.
  process.on("SIGTERM", () => handle.close());
}
```
