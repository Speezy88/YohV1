**Goal:** Home shows today's Plan as an ordered checklist next to a Calendar Day View — both computed server-side — with skeleton loads, the two named empty states, live re-fetch on a Plan-change SSE hint, and the Feb 19 confetti keyed to the host's date, never the browser's.

**Architecture:** `app/home-view.ts` (`getHomeView`) is the one new interaction use-case: it reads today's stored `Plan` (`memory-store.ts`'s `getPlan`, unchanged), a live read of today's primary-calendar events (`calendar-adapter.ts`'s `readCalendarEvents` — a single per-request read, not a background poll, per the implementer note: nothing here subscribes to calendar changes), and a live read of Notion Tasks (`readNotionTasks`) to know each Plan work-block's CURRENT completion status (the stored Plan only snapshots a Task's title at generation time, never its status). It shapes the result into `types/api.ts`'s new `HomeViewResponse` — `today` (the host-timezone date string, so the client's Feb-19 check never touches `new Date()`), `plan.rows` in the stored Plan's own order, and `calendar.blocks` (Yoh-owned `work`/`break` blocks from the Plan, plus live-read events as `kind: "fixed"`) — leaving "add ` (fixed)`" and all styling to the client, since that's presentation, not placement (AD-17 governs order/placement, not label text). **The Plan-change outbox hint (Ruling R4):** `memory-store.ts`'s `putPlan` gains an optional `onCommit(db)` hook run inside its own `writeTx`, right before it returns — the two files that ever call `putPlan` (`rituals/morning-ritual.ts`, `rituals/mid-day-reflow.ts`) pass `(db) => appendOutboxInTx(db, {topic: "plan", entityId: plan.date})`, so the outbox row commits atomically with the Plan write without `memory-store.ts` ever importing `notification-store.ts` or either ritual file touching the `outbox` table directly (AD-10 ownership intact — each owner's own `...InTx` function is what runs inside the shared transaction). On the client, Story 7.7's `events.ts`/`connectEventStream` becomes a single shared connection (`web/src/lib/eventBus.ts`) multiplexed to multiple topic-filtered subscribers, since Home is now the SSE stream's second real consumer alongside notifications — `notifications.ts` is refactored to subscribe to the bus instead of opening its own `EventSource`. `web/src/lib/homeView.ts` is Home's own small store (same `useSyncExternalStore` shape as `notifications.ts`), re-fetching `GET /api/home` on a `topic: "plan"` hint. `web/src/pages/Home.tsx` renders the checklist and Calendar Day View from that one response, registers a `"home-data"` readiness gate (Story 7.6's `useReadinessGate`, extended exactly as designed), and fires the Feb-19 confetti keyed to `response.today`.

**Tech Stack:** existing `memory-store.ts`/`calendar-adapter.ts`/`notion-adapter.ts` (no new adapters), `useSyncExternalStore` (client store, matching Story 7.7's convention), CSS keyframes for confetti.

## Global Constraints

- Every order and placement Home renders is computed server-side (`getHomeView`); the client only renders what it's given.
- Plan Rows render in exactly the stored Plan's own block order — never re-sorted client-side.
- `memory-store.ts` still never imports `notification-store.ts`; `notification-store.ts`'s tables are touched only through its own exported `...InTx`/convenience functions, called from inside whichever caller's `writeTx` is already open (AD-10).
- No calendar polling is added — `readCalendarEvents` runs once per `/api/home` request, never on a timer.
- Cold loads show skeleton rows/cards matching the layout, never a static spinner (UX-DR48).
- "Today" for the Feb 19 confetti check is the server's `today` string from the response, never `new Date()` in the browser.
- Confetti never plays under reduced motion.

```ts
  readModifyWrite<T>(
    kind: string,
    id: string,
    expectedVersion: number | undefined,
    modify: (current: StoredRecord<T> | undefined) => T,
    onCommit?: (db: Database.Database) => void,
  ): StoredRecord<T> {
    return this.connection.writeTx((db): StoredRecord<T> => {
      const row = this.selectRow(kind, id);
      const actualVersion = row?.version;

      if (expectedVersion !== actualVersion) {
        throw new ConflictError(/* unchanged */);
      }

      const current = row ? this.rowToRecord<T>(row) : undefined;
      const nextData = modify(current);
      const nextVersion = (row?.version ?? 0) + 1;
      const updatedAt = new Date().toISOString();

      db.prepare(/* unchanged INSERT ... ON CONFLICT ... */).run({ kind, id, data: JSON.stringify(nextData), version: nextVersion, updatedAt });

      const result: StoredRecord<T> = { kind, id, data: nextData, version: nextVersion, updatedAt };
      onCommit?.(db);
      return result;
    });
  }
```

```ts
/**
 * Stores `plan` under its own `date`. `onCommit`, if given, runs inside the
 * SAME `writeTx` right before this returns (Story 7.8, Ruling R4) — the two
 * callers below use it to append a Plan-change outbox hint atomically,
 * without this file ever importing `notification-store.ts` (AD-10:
 * `appendOutboxInTx` is the OTHER owner's `...InTx` function, called from
 * inside the caller's transaction, never reached into directly here).
 */
export function putPlan(store: MemoryStore, plan: Plan, onCommit?: (db: Database.Database) => void): StoredRecord<Plan> {
  const current = store.getRecord<Plan>(PLAN_KIND, plan.date);
  return store.readModifyWrite<Plan>(PLAN_KIND, plan.date, current?.version, () => plan, onCommit);
}
```

```ts
/**
 * src/app/home-view.ts
 *
 * Story 7.8, AD-16/AD-17: Home's one server-computed view. Reads today's
 * stored Plan (unchanged from Phase 1), a live read of today's primary
 * calendar (once per request — no polling), and a live read of Notion
 * Tasks for current completion status (the stored Plan only ever
 * snapshots a Task's TITLE at generation time, never its live status).
 */
import { getPlan } from "../adapters/memory-store.ts";
import type { MemoryStore } from "../adapters/memory-store.ts";
import { localIsoDate } from "../rituals/ritual-shared.ts";
import type { CalendarEvent, ExternalId, PlanBlock, Task } from "../types/domain.ts";
import type { HomeCalendarBlock, HomePlanRow, HomeViewResponse } from "../types/api.ts";
import type { Result, YohError } from "../types/domain.ts";

export interface HomeViewDeps {
  readonly store: MemoryStore;
  /** `calendar-adapter.ts`'s `readCalendarEvents`, pre-bound to its client/config. Called once per request — never on a timer. */
  readonly readCalendarEvents: () => Promise<readonly CalendarEvent[]>;
  /** `notion-adapter.ts`'s `readNotionTasks`, pre-bound. Used only for each Task's CURRENT `status`. */
  readonly readTasks: () => Promise<{ readonly tasks: readonly Task[] }>;
  readonly timeZone: string;
  readonly now: () => Date;
}

function describeError(err: unknown): string {
  return err instanceof Error ? err.message : String(err);
}

function toFixedBlock(event: CalendarEvent, nowMs: number): HomeCalendarBlock {
  return { id: event.id, kind: "fixed", label: event.title, start: event.start, end: event.end, completed: false, past: Date.parse(event.end) < nowMs };
}

export async function getHomeView(deps: HomeViewDeps, _input: Record<string, never>): Promise<Result<HomeViewResponse, YohError>> {
  const now = deps.now();
  const nowMs = now.getTime();
  const today = localIsoDate(now, deps.timeZone);

  let calendarEvents: readonly CalendarEvent[];
  try {
    calendarEvents = await deps.readCalendarEvents();
  } catch (err) {
    return { ok: false, error: { kind: "unreachable", message: `home-view: could not read today's calendar — ${describeError(err)}`, detail: err } };
  }

  const stored = getPlan(deps.store, today);
  const fixedBlocks = calendarEvents.map((e) => toFixedBlock(e, nowMs));

  if (!stored) {
    return { ok: true, value: { today, plan: undefined, calendar: { blocks: fixedBlocks } } };
  }

  let tasksById = new Map<ExternalId, Task>();
  try {
    const { tasks } = await deps.readTasks();
    tasksById = new Map(tasks.map((t) => [t.id, t]));
  } catch {
    // A Notion outage must not blank Home's Plan checklist — rows still
    // render from the Plan's own snapshot; completion just falls back to
    // "not completed" until the next successful read.
  }

  const isCompleted = (block: PlanBlock): boolean => block.kind === "work" && block.taskId !== undefined && tasksById.get(block.taskId)?.status === "completed";

  const rows: HomePlanRow[] = [];
  for (const block of stored.data.blocks) {
    if (block.kind !== "work" || block.taskId === undefined) continue;
    rows.push({
      blockId: block.id,
      taskId: block.taskId,
      label: block.label,
      start: block.start,
      end: block.end,
      completed: isCompleted(block),
      past: Date.parse(block.end) < nowMs,
    });
  }

  const ownedBlocks: HomeCalendarBlock[] = stored.data.blocks
    .filter((b): b is PlanBlock & { kind: "work" | "break" } => b.kind === "work" || b.kind === "break")
    .map((b) => ({ id: b.id, kind: b.kind, label: b.label, start: b.start, end: b.end, completed: isCompleted(b), past: Date.parse(b.end) < nowMs }));

  const blocks = [...ownedBlocks, ...fixedBlocks].sort((a, b) => Date.parse(a.start) - Date.parse(b.start));

  return { ok: true, value: { today, plan: { rows }, calendar: { blocks } } };
}
```

```ts
/**
 * web/src/lib/eventBus.ts
 *
 * Story 7.8: ONE `connectEventStream` connection (AD-18: "one SSE stream
 * per client"), multiplexed to as many topic-filtered subscribers as the
 * app needs. Story 7.7's `notifications.ts` was the first, direct caller
 * of `connectEventStream` — refactored here to subscribe to this bus
 * instead, now that Home (this story) is the second real consumer.
 */
import { connectEventStream, type EventHint } from "./events.ts";

export type EventBusHint = EventHint;
type HintListener = (hint: EventBusHint) => void;
type StatusListener = () => void;

const hintListeners = new Set<HintListener>();
const unreachableListeners = new Set<StatusListener>();
const reachableListeners = new Set<StatusListener>();
let activeConnections = 0;
let stopUnderlying: (() => void) | undefined;

/** Idempotent — the underlying `EventSource` opens once no matter how many callers start the bus; it closes only once every caller has stopped. */
export function startEventBus(): () => void {
  activeConnections++;
  if (!stopUnderlying) {
    stopUnderlying = connectEventStream({
      onHint: (hint) => hintListeners.forEach((l) => l(hint)),
      onUnreachable: () => unreachableListeners.forEach((l) => l()),
      onReachable: () => reachableListeners.forEach((l) => l()),
    });
  }
  let stopped = false;
  return () => {
    if (stopped) return;
    stopped = true;
    activeConnections--;
    if (activeConnections <= 0) {
      stopUnderlying?.();
      stopUnderlying = undefined;
    }
  };
}

export function onHint(listener: HintListener): () => void {
  hintListeners.add(listener);
  return () => hintListeners.delete(listener);
}
export function onUnreachable(listener: StatusListener): () => void {
  unreachableListeners.add(listener);
  return () => unreachableListeners.delete(listener);
}
export function onReachable(listener: StatusListener): () => void {
  reachableListeners.add(listener);
  return () => reachableListeners.delete(listener);
}
```

```ts
/**
 * web/src/lib/homeView.ts
 *
 * Story 7.8: Home's own small store, same `useSyncExternalStore` shape as
 * `notifications.ts`. Re-fetches `GET /api/home` on a `topic: "plan"` hint
 * from the shared event bus.
 */
import { useSyncExternalStore } from "react";
import { onHint } from "./eventBus.ts";
import { apiClient } from "./apiClient.ts";
import type { HomeViewResponse } from "../../../src/types/api.ts";

export type HomeViewState = { readonly status: "loading" } | { readonly status: "loaded"; readonly value: HomeViewResponse } | { readonly status: "error"; readonly message: string };

let state: HomeViewState = { status: "loading" };
const listeners = new Set<() => void>();
function notify(): void {
  listeners.forEach((l) => l());
}
function snapshot(): HomeViewState {
  return state;
}

async function refetch(): Promise<void> {
  try {
    const res = await apiClient.home.$get();
    const result = await res.json();
    state = result.ok ? { status: "loaded", value: result.value } : { status: "error", message: result.error.message };
  } catch (err) {
    state = { status: "error", message: err instanceof Error ? err.message : String(err) };
  }
  notify();
}

export function useHomeView(): HomeViewState {
  return useSyncExternalStore(
    (onChange) => {
      listeners.add(onChange);
      return () => listeners.delete(onChange);
    },
    snapshot,
  );
}

export function startHomeViewStream(): () => void {
  void refetch();
  return onHint((hint) => {
    if (hint.topic === "plan") void refetch();
  });
}
```

```tsx
/**
 * web/src/components/Confetti.tsx — DESIGN.md `Birthday Confetti`, UX-DR46.
 * `today` comes from the SERVER's HomeViewResponse — never the browser's
 * clock (Consistency Conventions). Persists "already shown" per day in
 * localStorage, wrapped.
 */
import { useEffect, useState } from "react";
import { useReducedMotion } from "../hooks/useReducedMotion.ts";

function alreadyShownToday(today: string): boolean {
  try {
    return localStorage.getItem("yoh-confetti-shown") === today;
  } catch {
    return false;
  }
}
function markShown(today: string): void {
  try {
    localStorage.setItem("yoh-confetti-shown", today);
  } catch {
    // Blocked storage — confetti may replay on a later view the same day; harmless.
  }
}

export function Confetti({ today }: { readonly today: string }): React.JSX.Element | null {
  const reducedMotion = useReducedMotion();
  const [show, setShow] = useState(false);

  useEffect(() => {
    if (reducedMotion) return;
    if (!today.endsWith("-02-19")) return;
    if (alreadyShownToday(today)) return;
    markShown(today);
    setShow(true);
    const timer = setTimeout(() => setShow(false), 1500);
    return () => clearTimeout(timer);
  }, [today, reducedMotion]);

  if (!show) return null;
  const pieces = Array.from({ length: 30 }, (_, i) => i);
  return (
    <div data-testid="confetti" className="pointer-events-none fixed inset-0 z-30 overflow-hidden">
      {pieces.map((i) => (
        <span
          key={i}
          className={i % 2 === 0 ? "absolute size-2 rounded-full bg-accent-solid" : "absolute size-2 rounded-full bg-ink-secondary"}
          style={{ left: `${(i * 37) % 100}%`, top: "-5%", animation: `confetti-fall 1.4s ease-in ${((i * 53) % 400) / 1000}s forwards` }}
        />
      ))}
    </div>
  );
}
```

```tsx
/**
 * web/src/components/CalendarDayView.tsx — DESIGN.md `Calendar Day View` /
 * `Calendar Block`, UX-DR32. Today only. Yoh-owned (`work`/`break`) render
 * as raised blocks; `fixed` (non-Yoh) render cross-hatched, no shadow,
 * suffixed " (fixed)". Past/completed blocks are visibly read-only.
 */
import type { HomeCalendarBlock } from "../../../src/types/api.ts";

const DAY_START_HOUR = 6;
const DAY_END_HOUR = 23;
const WINDOW_MINUTES = (DAY_END_HOUR - DAY_START_HOUR) * 60;

function offsetPercent(iso: string): number {
  const d = new Date(iso);
  const minutes = d.getUTCHours() * 60 + d.getUTCMinutes() - DAY_START_HOUR * 60;
  return Math.max(0, Math.min(100, (minutes / WINDOW_MINUTES) * 100));
}

export function CalendarDayView({ blocks }: { readonly blocks: readonly HomeCalendarBlock[] }): React.JSX.Element {
  const hours = Array.from({ length: DAY_END_HOUR - DAY_START_HOUR + 1 }, (_, i) => DAY_START_HOUR + i);

  return (
    <div className="relative h-full rounded-lg border-l border-rim-structural pl-2" data-testid="calendar-day-view">
      {hours.map((h) => (
        <div key={h} className="absolute left-0 w-full border-t border-rim-structural/30 text-caption text-ink-secondary" style={{ top: `${((h - DAY_START_HOUR) / (DAY_END_HOUR - DAY_START_HOUR)) * 100}%` }}>
          {h % 12 === 0 ? 12 : h % 12}
          {h < 12 ? "AM" : "PM"}
        </div>
      ))}
      {blocks.map((b) => (
        <div
          key={b.id}
          aria-disabled={b.past || b.completed}
          className={
            b.kind === "fixed"
              ? "absolute left-8 right-2 rounded-sm border border-rim-structural bg-[repeating-linear-gradient(45deg,var(--color-event-fixed-stripe-a),var(--color-event-fixed-stripe-a)_6px,var(--color-event-fixed-stripe-b)_6px,var(--color-event-fixed-stripe-b)_12px)] px-2 py-1 text-caption text-event-fixed-ink"
              : `absolute left-8 right-2 rounded-sm bg-surface-raised px-2 py-1 text-caption text-ink-primary shadow-[3px_3px_7px_var(--color-shadow-dark),-3px_-3px_7px_var(--color-shadow-light)] ${b.past || b.completed ? "opacity-50" : ""}`
          }
          style={{ top: `${offsetPercent(b.start)}%`, height: `${Math.max(2, offsetPercent(b.end) - offsetPercent(b.start))}%` }}
        >
          {b.kind === "fixed" ? `${b.label} (fixed)` : b.label}
        </div>
      ))}
    </div>
  );
}
```
