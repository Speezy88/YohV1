# Story 7.7: In-App Notification Overlay — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Web App shows a durable in-app notification, on whatever page is open, within a few seconds of it being created server-side — as a glass card Spencer can click to jump to its target, or dismiss. A dropped connection is itself surfaced honestly: reconnect replays anything missed, and a connection that can't recover shows a local "Yoh server unreachable" notification of the same shape. No silent failure.

**Architecture:** `web/src/lib/events.ts` wraps the browser's native `EventSource` against `GET /api/events`. On the browser's OWN internal reconnect (a transient drop while the same `EventSource` object is still alive), the browser automatically resends `Last-Event-ID` from the last event it received — no client code needed for that case (AD-18). The gap this file closes is the OTHER case: after `UNREACHABLE_AFTER_MS` of no successful message/open, the client gives up on that `EventSource`, closes it, raises the local unreachable notification, and later opens a **brand-new** `EventSource` — which has no memory of `Last-Event-ID` (the browser only auto-sends that header on ITS OWN reconnect of the SAME object; there is no API to set a custom header on a fresh one). `events.ts` tracks the last `seq` it saw itself and appends it as a `?lastEventId=` query parameter on every fresh open; `shell/server.ts`'s `/api/events` route (Story 7.3) is extended to accept that query parameter as a fallback to the `Last-Event-ID` header, so a fresh reconnect after a hard drop still replays from the right `seq`. `web/src/lib/notifications.ts` owns the notification list as one small store (`useSyncExternalStore`, the same shape Story 7.6's `readiness.ts` already established): a `topic: "notification"` hint triggers a re-fetch of `GET /api/notifications` through the typed `apiClient` (Story 7.5); the store also accepts a purely client-side synthetic record (`kind: "operational"`, no `deepLink`) for the unreachable case, which is never sent to or read from the server. `web/src/components/NotificationOverlay.tsx` renders the newest three, newest-first, as glass cards; clicking one with a `deepLink` uses `PageNavigationContext` (a small context `PageShell`, Story 7.6, now provides) to jump to the matching page and marks it read via `apiClient`; an `operational` notification is message-only and un-clickable-to-navigate. `@supports (backdrop-filter: blur(1px))` gates the real glass material; browsers without it (older Windows Chromium/Edge builds) get an opaque `surface-raised` fill with the identical rim, verified manually.

**Tech Stack:** Native `EventSource`, React `useSyncExternalStore`, `hono/client`'s typed `apiClient` (Story 7.5), CSS `@supports`.

**Spec:** SDD plan Task 7 (`_bmad-output/implementation-artifacts/sdd-plan-YohV1-phase2.md`); `ARCHITECTURE-SPINE.md` AD-18 (live delivery, `Last-Event-ID` replay); `DESIGN.md` `in-app-notification`/glass-surface components, State-tied motion (toast enter); `EXPERIENCE.md` In-App Notifications table, Component Patterns.

## Global Constraints

- SSE hints carry no data — every hint triggers a re-fetch through the ordinary API, never a hint-carried payload rendered directly.
- A notification's `kind` is the closed `NotificationKind` union (Story 7.2's `types/api.ts`) — `web/`'s own local synthetic unreachable record uses `kind: "operational"`, a real member, never an invented eighth kind.
- Up to three notifications show at once, newest-first; a failure notification is never auto-dismissed unseen.
- An `operational` notification is message-only: no deep link, never clickable-to-navigate.
- Enter animation reads `useReducedMotion` (Story 7.5): 0.55s drop+fade with a pulsing dot normally, fade-only with no pulse under reduced motion.
- `aria-live="polite"` announces a new notification.
- `@supports (backdrop-filter: blur(1px))` gates the glass material; the fallback uses the same rim (`--color-rim-interactive`) so the boundary never disappears.

Create `web/src/lib/events.ts`:

```ts
/**
 * web/src/lib/events.ts
 *
 * Story 7.7, AD-18: the one `GET /api/events` client. The browser's native
 * `EventSource` already resends `Last-Event-ID` on ITS OWN transient
 * reconnect (same object, connection drops and comes back) — nothing to do
 * for that case. This file handles the case AD-18 doesn't cover for free: a
 * connection that never recovers. After `UNREACHABLE_AFTER_MS` with no
 * open/message, it gives up on that `EventSource`, tells the caller
 * (`onUnreachable`, Task 2 shows the local notification), and later opens a
 * FRESH `EventSource` — which has no memory of `Last-Event-ID` (there is no
 * way to set a custom header on it) — so this file appends the last `seq`
 * it saw as `?lastEventId=` instead, and `shell/server.ts`'s route (Task 1
 * above) reads that as a fallback to the header.
 */
export interface EventHint {
  readonly seq: number;
  readonly topic: string;
  readonly entityId: string;
}

export interface EventStreamHandlers {
  onHint(hint: EventHint): void;
  onUnreachable(): void;
  onReachable(): void;
}

const UNREACHABLE_AFTER_MS = 15_000;
const RECONNECT_BACKOFF_MS = 5_000;

export function connectEventStream(handlers: EventStreamHandlers): () => void {
  let lastSeq = 0;
  let source: EventSource | undefined;
  let unreachableTimer: ReturnType<typeof setTimeout> | undefined;
  let reconnectTimer: ReturnType<typeof setTimeout> | undefined;
  let stopped = false;

  function armUnreachableTimer(): void {
    clearTimeout(unreachableTimer);
    unreachableTimer = setTimeout(() => {
      handlers.onUnreachable();
      source?.close();
      reconnectTimer = setTimeout(open, RECONNECT_BACKOFF_MS);
    }, UNREACHABLE_AFTER_MS);
  }

  function open(): void {
    if (stopped) return;
    const url = lastSeq > 0 ? `/api/events?lastEventId=${lastSeq}` : "/api/events";
    source = new EventSource(url);
    armUnreachableTimer();

    source.onopen = () => {
      clearTimeout(unreachableTimer);
      armUnreachableTimer();
      handlers.onReachable();
    };
    source.onmessage = (event: MessageEvent<string>) => {
      clearTimeout(unreachableTimer);
      armUnreachableTimer();
      const hint = JSON.parse(event.data) as EventHint;
      lastSeq = hint.seq;
      handlers.onHint(hint);
    };
    source.onerror = () => {
      // The browser retries this SAME object on its own (sending its own
      // Last-Event-ID automatically) unless armUnreachableTimer's deadline
      // passes first — no action needed here beyond letting that timer run.
    };
  }

  open();

  return () => {
    stopped = true;
    clearTimeout(unreachableTimer);
    clearTimeout(reconnectTimer);
    source?.close();
  };
}
```

```ts
/**
 * web/src/lib/notifications.ts
 *
 * Story 7.7: the notification list `NotificationOverlay` renders — a
 * `useSyncExternalStore` store (same convention as `readiness.ts`, Story
 * 7.6), fed by `connectEventStream` (Task 1). A `topic: "notification"`
 * hint re-fetches `GET /api/notifications`; every other topic is ignored
 * here (Story 7.8's Home listens for `topic: "plan"` on its own). Also
 * accepts one purely client-side synthetic record for "host unreachable" —
 * never sent to or read from the server, marked `kind: "operational"` (a
 * real closed-union member, AD-18) with no `deepLink`.
 */
import { useSyncExternalStore } from "react";
import { connectEventStream } from "./events.ts";
import { apiClient } from "./apiClient.ts";
import type { NotificationRecord } from "../../../src/types/api.ts";

const MAX_SHOWN = 3;

let records: NotificationRecord[] = [];
const listeners = new Set<() => void>();

function notify(): void {
  listeners.forEach((l) => l());
}

function snapshot(): readonly NotificationRecord[] {
  return records;
}

function upsertMany(fresh: readonly NotificationRecord[]): void {
  const byId = new Map(records.map((r) => [r.id, r]));
  for (const r of fresh) byId.set(r.id, r);
  records = [...byId.values()].sort((a, b) => Date.parse(b.createdAt) - Date.parse(a.createdAt)).slice(0, MAX_SHOWN);
  notify();
}

async function refetch(): Promise<void> {
  const res = await apiClient.notifications.$get();
  const result = await res.json();
  if (result.ok) upsertMany(result.value.notifications);
}

let localIdCounter = 0;

function addLocalUnreachable(): void {
  const record: NotificationRecord = {
    id: `local-unreachable-${Date.now()}-${localIdCounter++}`,
    kind: "operational",
    title: "Yoh server unreachable",
    body: "The connection to Yoh dropped and couldn't reconnect. Retrying in the background.",
    createdAt: new Date().toISOString(),
  };
  records = [record, ...records].slice(0, MAX_SHOWN);
  notify();
}

export function useNotifications(): readonly NotificationRecord[] {
  return useSyncExternalStore(
    (onChange) => {
      listeners.add(onChange);
      return () => listeners.delete(onChange);
    },
    snapshot,
  );
}

/** Marks a server-backed record read via the API, or just removes a local synthetic one — either way it leaves the visible stack. */
export function dismissNotification(id: string): void {
  records = records.filter((r) => r.id !== id);
  notify();
  if (!id.startsWith("local-unreachable-")) {
    void apiClient.notifications[":id"].read.$post({ param: { id } });
  }
}

/** Starts the SSE subscription driving this store. Call once, near the app root; returns a stop function. */
export function startNotificationStream(): () => void {
  void refetch(); // pick up anything already unread on first load
  return connectEventStream({
    onHint: (hint) => {
      if (hint.topic === "notification") void refetch();
    },
    onUnreachable: addLocalUnreachable,
    onReachable: () => {},
  });
}
```

```tsx
/**
 * web/src/components/NotificationOverlay.tsx
 *
 * Story 7.7, DESIGN.md `in-app-notification`, UX-DR45. Glass card, 3px
 * accent-solid left bar, pulsing dot (skipped under reduced motion), one
 * line, whole surface clickable. `operational` is message-only.
 */
import { PAGES } from "../lib/pages.ts";
import { usePageNavigationContext } from "../lib/navigationContext.tsx";
import { dismissNotification, useNotifications } from "../lib/notifications.ts";
import { useReducedMotion } from "../hooks/useReducedMotion.ts";
import { Icon } from "./icons/Icon.tsx";

function resolveDeepLinkIndex(deepLink: string): number | undefined {
  const id = deepLink.replace(/^\//, "");
  const index = PAGES.findIndex((p) => p.id === id);
  return index === -1 ? undefined : index;
}

export function NotificationOverlay(): React.JSX.Element {
  const notifications = useNotifications();
  const nav = usePageNavigationContext();
  const reducedMotion = useReducedMotion();

  const handleClick = (id: string, deepLink: string | undefined): void => {
    if (deepLink) {
      const index = resolveDeepLinkIndex(deepLink);
      if (index !== undefined) nav.goTo(index);
    }
    dismissNotification(id);
  };

  return (
    <div className="pointer-events-none fixed right-4 top-4 z-40 flex flex-col gap-2" role="status" aria-live="polite">
      {notifications.map((n) => (
        <div
          key={n.id}
          data-testid="notification-card"
          onClick={() => handleClick(n.id, n.deepLink)}
          className={
            (reducedMotion ? "animate-none opacity-100" : "animate-[notification-drop_0.55s_ease-out]") +
            " pointer-events-auto flex w-80 cursor-pointer items-start gap-2 rounded-md border-l-[3px] border-accent-solid p-3 text-body text-ink-primary notification-glass"
          }
        >
          {!reducedMotion && <span className="mt-1 size-2 shrink-0 animate-pulse rounded-full bg-accent-solid" aria-hidden />}
          <span className="flex-1">{n.body}</span>
          <button
            type="button"
            aria-label="Dismiss notification"
            onClick={(e) => {
              e.stopPropagation();
              dismissNotification(n.id);
            }}
            className="shrink-0"
          >
            <Icon path="M6 6 L18 18 M18 6 L6 18" label="Dismiss" />
          </button>
        </div>
      ))}
    </div>
  );
}
```
