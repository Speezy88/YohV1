# Story 6.6: Confirm-Gated Calendar Editing Beyond Yoh-Owned Events — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spencer can ask Yoh (in chat) to move, resize, or create a time block on his real Calendar — including events Yoh didn't create — and see exactly what will change before anything is touched. A non-Yoh event can never be deleted through this path, not even by a coding mistake, because `CalendarEditChange` has no `delete` variant to construct.

**Architecture:** `token-store.ts` gains a SECOND, separately-scoped `OAuth2Client` (`calendar.events`, read/write across all accessible calendars) alongside the existing narrow one — both sole-constructed/held there (AD-10/AD-13). `calendar-adapter.ts` gains a genuinely separate `CalendarBroadClient` type (distinct from `CalendarReadClient`/`CalendarWriteClient`, same "no accidentally-widened scope" pattern those two already establish) plus `resolveCalendarEditRoute`/`proposeCalendarEdit`/`proposeNewCalendarEvent`/`applyCalendarEdit`. `types/domain.ts` gains `CalendarEditChange`, a union of exactly `move`/`resize`/`create` — no `delete` variant exists in the type system (AD-13's core guarantee). Since parsing "move my 3pm meeting to 4:30" deterministically isn't realistic, `llm-adapter.ts` gains `draftCalendarEditRequest`, mirroring `draftNotionPageFields`'s "LLM extracts structured fields from free text, chat-cli.ts validates before trusting them" pattern. `chat-cli.ts` wires a new deterministic trigger (keyword heuristic, same tier as every other trigger check), looks up the named event among TODAY's primary-calendar events (the same day-window `readCalendarEvents` already reads), routes through `resolveCalendarEditRoute`, shows the resulting `Proposal<CalendarEditChange>`, and on "yes" calls `applyCalendarEdit`.

**Scope note (deliberate, documented boundary):** event lookup in this story is scoped to TODAY's PRIMARY calendar only (mirroring how Data-Completeness/Mid-Day Re-Flow/Blocker reports already treat "today" as the operative window everywhere else in this codebase) — not an arbitrary date range or the "Yoh Plan" calendar. This means `resolveCalendarEditRoute`'s `'owned'` branch, while fully implemented and unit-tested in isolation, is not reachable through THIS story's own chat-cli wiring (a "Yoh Plan" event is never among the candidates chat-cli looks up) — it exists for AD-13's own structural completeness and any future caller. Documented here rather than left implicit.

**Tech Stack:** `google-auth-library` (`token-store.ts` only, per AD-10), `@googleapis/calendar`, `@anthropic-ai/sdk` (via `AnthropicMessagesClient`), `node:test`.

**Spec:** `_bmad-output/planning-artifacts/epics.md` Story 6.6 (lines 945–974); `ARCHITECTURE-SPINE.md` AD-3, AD-4, AD-10, AD-13.

## Global Constraints

- `CalendarEditChange` has exactly `move`/`resize`/`create` variants — never `delete` (AD-13).
- The automatic "Yoh Plan" path's own credential (the existing narrow `OAuth2Client`) must never be handed the new broader-scoped client — `token-store.ts` constructs and holds both, separately (AD-10).
- `'owned'` events stay on AD-4's existing automatic path — this new confirm-gated mechanism must decline to touch an event `resolveCalendarEditRoute` reports as `'owned'`, not silently allow it through a second code path (AD-13: "`'owned'` stays on AD-4's existing automatic path, unchanged").
- `applyCalendarEdit` re-reads the live event and rejects a stale `move`/`resize` proposal (AD-3) — but skips that re-read for `create`, which has no live entity yet (AD-3's `NotionPageDraft`-equivalent exemption).
- No live Google account is available in this environment — every test injects a fake client (the same convention `notion-adapter.ts`/`calendar-adapter.ts`'s existing tests already use).

```ts
export class TokenStore {
  private readonly client: OAuth2Client;
  private readonly broadClient: OAuth2Client;
  private readonly tokenFilePath: string;

  constructor(config: GoogleOAuthConfig) {
    this.tokenFilePath = config.tokenFilePath;
    this.client = new OAuth2Client({
      clientId: config.clientId,
      clientSecret: config.clientSecret,
      redirectUri: config.redirectUri,
    });
    this.broadClient = new OAuth2Client({
      clientId: config.clientId,
      clientSecret: config.clientSecret,
      redirectUri: config.redirectUri,
    });

    const stored = this.readStoredToken();
    const refreshToken = stored?.refreshToken ?? config.initialRefreshToken;
    if (refreshToken) {
      this.client.setCredentials({ refresh_token: refreshToken });
      if (!stored) {
        this.writeStoredToken({ refreshToken });
      }
    }

    const broadRefreshToken = stored?.broadRefreshToken ?? config.broadInitialRefreshToken;
    if (broadRefreshToken) {
      this.broadClient.setCredentials({ refresh_token: broadRefreshToken });
      if (!stored?.broadRefreshToken) {
        this.writeStoredToken({ broadRefreshToken });
      }
    }

    this.client.on("tokens", (tokens: Credentials) => {
      if (tokens.refresh_token) {
        this.writeStoredToken({ refreshToken: tokens.refresh_token });
      }
    });
    this.broadClient.on("tokens", (tokens: Credentials) => {
      if (tokens.refresh_token) {
        this.writeStoredToken({ broadRefreshToken: tokens.refresh_token });
      }
    });
  }

  getOAuth2Client(): OAuth2Client {
    return this.client;
  }

  /** The second, broader-scoped `OAuth2Client` (AD-13, Story 6.6) — used ONLY by `calendar-adapter.ts`'s FR-27 functions, never AD-4's automatic path. */
  getBroadOAuth2Client(): OAuth2Client {
    return this.broadClient;
  }

  getCalendarId(): string | undefined {
    return this.readStoredToken()?.calendarId;
  }

  setCalendarId(calendarId: string): void {
    this.writeStoredToken({ calendarId });
  }

  private readStoredToken(): StoredGoogleToken | undefined {
    if (!existsSync(this.tokenFilePath)) return undefined;
    const raw = readFileSync(this.tokenFilePath, "utf8");
    return JSON.parse(raw) as StoredGoogleToken;
  }

  /** Merges `patch` onto whatever is currently on disk (never wholesale-replaces) — so the narrow client's refresh, the broad client's refresh, and the "Yoh Plan" calendar id can each be updated independently without clobbering the other two. */
  private writeStoredToken(patch: Partial<StoredGoogleToken>): void {
    const dir = dirname(this.tokenFilePath);
    if (!existsSync(dir)) {
      mkdirSync(dir, { recursive: true });
    }
    const current = this.readStoredToken();
    const refreshToken = patch.refreshToken ?? current?.refreshToken ?? this.client.credentials.refresh_token;
    if (!refreshToken) {
      throw new Error("token-store: cannot persist token state before a narrow refresh token exists");
    }
    const onDisk: StoredGoogleToken = {
      refreshToken,
      ...((patch.calendarId ?? current?.calendarId) ? { calendarId: patch.calendarId ?? current?.calendarId } : {}),
      ...((patch.broadRefreshToken ?? current?.broadRefreshToken)
        ? { broadRefreshToken: patch.broadRefreshToken ?? current?.broadRefreshToken }
        : {}),
    };
    writeFileSync(this.tokenFilePath, JSON.stringify(onDisk, null, 2), "utf8");
  }
}
```

/**
 * Checks whether `eventId` (on `calendarId`) is a Yoh-created "Yoh Plan"
 * event — the SAME `PLAN_BLOCK_ID_EXTENDED_PROPERTY` tag AD-4's automatic
 * path already stamps every "Yoh Plan" event with. Every FR-27 caller
 * (`shell/chat-cli.ts`) routes through this first; `'owned'` means this
 * new confirm-gated path must decline and defer to AD-4's existing
 * automatic mechanism instead (Mid-Day Re-Flow) — it never proceeds to
 * `proposeCalendarEdit` for an `'owned'` result.
 */
export async function resolveCalendarEditRoute(
  client: CalendarBroadClient,
  calendarId: string,
  eventId: ExternalId,
): Promise<{ readonly kind: "owned" } | { readonly kind: "external" }> {
  const response = await client.events.get({ calendarId, eventId });
  const isYohOwned = Boolean(response.data.extendedProperties?.private?.[PLAN_BLOCK_ID_EXTENDED_PROPERTY]);
  return isYohOwned ? { kind: "owned" } : { kind: "external" };
}

  readonly kind: "move" | "resize";
  readonly newStart?: IsoDateTime;
  readonly newEnd?: IsoDateTime;
}

/**
 * Reads the live event (for its current start/end/etag) and returns a
 * `Proposal<CalendarEditChange>` describing exactly what would change —
 * writes nothing. `move` preserves the live event's own duration when
 * computing `newEnd`; `resize` carries the given `newEnd` straight through,
 * leaving `newStart` untouched (not part of a `resize` change at all).
 * `entityVersion` is the live event's `etag`, checked for staleness by
 * `applyCalendarEdit` (AD-3).
 */
export async function proposeCalendarEdit(
  client: CalendarBroadClient,
  calendarId: string,
  eventId: ExternalId,
  change: MoveOrResizeChange,
): Promise<Proposal<CalendarEditChange>> {
  const response = await client.events.get({ calendarId, eventId });
  const event = response.data;
  const liveStart = toIsoDateTime(event.start);
  const liveEnd = toIsoDateTime(event.end);
  const durationMs = new Date(liveEnd).getTime() - new Date(liveStart).getTime();

  const suggested: CalendarEditChange =
    change.kind === "move"
      ? {
          kind: "move",
          eventId,
          calendarId,
          newStart: change.newStart as IsoDateTime,
          newEnd: new Date(new Date(change.newStart as IsoDateTime).getTime() + durationMs).toISOString(),
        }
      : { kind: "resize", eventId, calendarId, newEnd: change.newEnd as IsoDateTime };

  const summary = event.summary ?? "this event";
  return {
    id: `calendar-edit-${eventId}-${Date.now()}`,
    kind: "calendar-edit",
    entityId: eventId,
    entityVersion: event.etag ?? "",
    suggested,
    reason:
      change.kind === "move"
        ? `Move "${summary}" to start at ${suggested.kind === "move" ? suggested.newStart : ""}`
        : `Resize "${summary}" to end at ${suggested.kind === "resize" ? suggested.newEnd : ""}`,
    createdAt: new Date().toISOString(),
  };
}

/** Input to `proposeNewCalendarEvent` — `create`, by definition, has no `eventId` yet. */
export interface CreateBlockChange {
  readonly calendarId: string;
  readonly title: string;
  readonly start: IsoDateTime;
  readonly end: IsoDateTime;
}

/**
 * Builds a `Proposal<CalendarEditChange>` for a NEW event — pure, no I/O:
 * there is no live entity to read yet, so unlike `proposeCalendarEdit` this
 * makes no client call at all (mirroring `NotionPageDraft`'s own no-live-
 * entity exemption under AD-3).
 */
export function proposeNewCalendarEvent(change: CreateBlockChange): Proposal<CalendarEditChange> {
  const suggested: CalendarEditChange = { kind: "create", calendarId: change.calendarId, title: change.title, start: change.start, end: change.end };
  return {
    id: `calendar-create-${Date.now()}`,
    kind: "calendar-edit",
    entityId: "new-event",
    entityVersion: "new",
    suggested,
    reason: `Create "${change.title}" from ${change.start} to ${change.end}`,
    createdAt: new Date().toISOString(),
  };
}

/**
 * Applies a confirmed `Proposal<CalendarEditChange>`. For `move`/`resize`:
 * re-reads the live event and compares its CURRENT `etag` against
 * `proposal.entityVersion` — a mismatch rejects with
 * `YohError.kind: "stale-proposal"` WITHOUT patching anything (AD-3); only
 * on a genuine match does it call `events.patch` with just the changed
 * field(s). For `create`: calls `events.insert` directly, skipping the
 * re-read entirely — there is no live entity to re-check (AD-3's
 * `NotionPageDraft`-equivalent exemption).
 */
export async function applyCalendarEdit(
  client: CalendarBroadClient,
  proposal: Proposal<CalendarEditChange>,
): Promise<Result<{ readonly eventId: string; readonly calendarId: string }, YohError>> {
  const change = proposal.suggested;

  if (change.kind === "create") {
    try {
      const response = await client.events.insert({
        calendarId: change.calendarId,
        requestBody: { summary: change.title, start: { dateTime: change.start }, end: { dateTime: change.end } },
      });
      const eventId = response.data.id;
      if (!eventId) {
        return { ok: false, error: { kind: "unreachable", message: "calendar-adapter: events.insert response is missing an id" } };
      }
      return { ok: true, value: { eventId, calendarId: change.calendarId } };
    } catch (err) {
      return {
        ok: false,
        error: {
          kind: "unreachable",
          message: `calendar-adapter: could not create the event — ${err instanceof Error ? err.message : String(err)}`,
          detail: err,
        },
      };
    }
  }

  let liveEvent: calendar_v3.Schema$Event;
  try {
    const response = await client.events.get({ calendarId: change.calendarId, eventId: change.eventId });
    liveEvent = response.data;
  } catch (err) {
    return {
      ok: false,
      error: {
        kind: "unreachable",
        message: `calendar-adapter: could not re-read the event before applying — ${err instanceof Error ? err.message : String(err)}`,
        detail: err,
      },
    };
  }

  if ((liveEvent.etag ?? "") !== proposal.entityVersion) {
    return {
      ok: false,
      error: {
        kind: "stale-proposal",
        message: `calendar-adapter: event "${change.eventId}" has changed since this proposal was generated`,
        detail: { eventId: change.eventId, expectedVersion: proposal.entityVersion, actualVersion: liveEvent.etag },
      },
    };
  }

  const requestBody: calendar_v3.Schema$Event =
    change.kind === "move" ? { start: { dateTime: change.newStart }, end: { dateTime: change.newEnd } } : { end: { dateTime: change.newEnd } };

  try {
    await client.events.patch({ calendarId: change.calendarId, eventId: change.eventId, requestBody });
    return { ok: true, value: { eventId: change.eventId, calendarId: change.calendarId } };
  } catch (err) {
    return {
      ok: false,
      error: {
        kind: "unreachable",
        message: `calendar-adapter: could not apply the edit — ${err instanceof Error ? err.message : String(err)}`,
        detail: err,
      },
    };
  }
}
```

// ============================================================================
// draftCalendarEditRequest (Story 6.6 / FR-27) — extracts a structured
// move/resize/create request from Spencer's free-text calendar-edit
// message. Never validates against the live Calendar itself (that's
// calendar-adapter.ts's job, via resolveCalendarEditRoute/
// proposeCalendarEdit) — this only turns prose (plus a `today`/`timeZone`
// anchor for resolving relative times) into structured, ISO-validated
// fields, failing closed to `undefined` on anything unparseable.
// ============================================================================

export type DraftedCalendarEditRequest =
  | { readonly kind: "move"; readonly eventTitle: string; readonly newStart: string }
  | { readonly kind: "resize"; readonly eventTitle: string; readonly newEnd: string }
  | { readonly kind: "create"; readonly title: string; readonly start: string; readonly end: string };

const DRAFT_CALENDAR_EDIT_MAX_TOKENS = 256;

function buildDraftCalendarEditSystemPrompt(today: string, timeZone: string, candidateEvents: readonly { readonly title: string; readonly start: string; readonly end: string }[]): string {
  const eventsList = candidateEvents.length > 0
    ? candidateEvents.map((e) => `  - "${e.title}": ${e.start} to ${e.end}`).join("\n")
    : "  (none)";
  return [
    "You are helping Yoh, Spencer's personal planning assistant, turn a chat request into a structured Calendar edit.",
    `Today's date is ${today}, Spencer's timezone is ${timeZone}. Resolve any relative time Spencer gives (e.g. "4pm", "in an hour") into a full ISO-8601 UTC datetime (e.g. "2026-09-18T20:00:00.000Z").`,
    "Today's known calendar events (for matching an event Spencer refers to by name):",
    eventsList,
    "Respond on ONE line, in exactly one of these forms:",
    "MOVE: <exact event title> | <new start, ISO-8601 UTC>",
    "RESIZE: <exact event title> | <new end, ISO-8601 UTC>",
    "CREATE: <title> | <start, ISO-8601 UTC> | <end, ISO-8601 UTC>",
    "or, if you cannot confidently determine this:",
    "NONE",
  ].join("\n");
}

function isValidIsoDateTime(raw: string): boolean {
  return !Number.isNaN(Date.parse(raw));
}

/**
 * Extracts a structured move/resize/create request from `line`. Returns
 * `undefined` — never throws for "couldn't extract" — when the response
 * doesn't match one of the three recognized forms, or any of its ISO
 * datetime fields fails to parse (never trusted blindly). A genuine
 * API/transport failure still propagates as a thrown error (AD-8).
 */
export async function draftCalendarEditRequest(
  client: AnthropicMessagesClient,
  line: string,
  today: string,
  timeZone: string,
  candidateEvents: readonly { readonly title: string; readonly start: string; readonly end: string }[],
): Promise<DraftedCalendarEditRequest | undefined> {
  const message = await client.messages.create({
    model: CLAUDE_CHAT_MODEL,
    max_tokens: DRAFT_CALENDAR_EDIT_MAX_TOKENS,
    system: buildDraftCalendarEditSystemPrompt(today, timeZone, candidateEvents),
    messages: [{ role: "user", content: line }],
  });

  const text = message.content
    .filter((block): block is Anthropic.TextBlock => block.type === "text")
    .map((block) => block.text)
    .join("\n")
    .trim();

  const moveMatch = /^MOVE:\s*(.+?)\s*\|\s*(.+)$/i.exec(text);
  if (moveMatch) {
    const [, eventTitle, newStart] = moveMatch;
    if (!isValidIsoDateTime(newStart!.trim())) return undefined;
    return { kind: "move", eventTitle: eventTitle!.trim(), newStart: newStart!.trim() };
  }

  const resizeMatch = /^RESIZE:\s*(.+?)\s*\|\s*(.+)$/i.exec(text);
  if (resizeMatch) {
    const [, eventTitle, newEnd] = resizeMatch;
    if (!isValidIsoDateTime(newEnd!.trim())) return undefined;
    return { kind: "resize", eventTitle: eventTitle!.trim(), newEnd: newEnd!.trim() };
  }

  const createMatch = /^CREATE:\s*(.+?)\s*\|\s*(.+?)\s*\|\s*(.+)$/i.exec(text);
  if (createMatch) {
    const [, title, start, end] = createMatch;
    if (!isValidIsoDateTime(start!.trim()) || !isValidIsoDateTime(end!.trim())) return undefined;
    return { kind: "create", title: title!.trim(), start: start!.trim(), end: end!.trim() };
  }

  return undefined;
}

 * names an event by title, matched case-insensitively among
 * `readCalendarEventsFn`'s result; `create` needs no lookup at all.
 * `resolveRoute` gates `move`/`resize`: an `'owned'` event (a "Yoh Plan"
 * block) is declined here — it stays on AD-4's existing automatic path
 * (Mid-Day Re-Flow), never this new confirm-gated one (AD-13).
 */
async function handleCalendarEditCommand(
  io: ChatCliIo,
  llmClient: AnthropicMessagesClient,
  line: string,
  today: IsoDate,
  timeZone: string,
  readCalendarEventsFn: () => Promise<readonly CalendarEvent[]>,
  resolveRoute: ResolveCalendarEditRouteFn,
  proposeEdit: ProposeCalendarEditFn,
  applyEdit: ApplyCalendarEditFn,
): Promise<void> {
  const events = await readCalendarEventsFn();

  let draft: DraftedCalendarEditRequest | undefined;
  try {
    draft = await draftCalendarEditRequest(
      llmClient,
      line,
      today,
      timeZone,
      events.map((e) => ({ title: e.title, start: e.start, end: e.end })),
    );
  } catch {
    draft = undefined;
  }

  if (!draft) {
    io.writeLine("I couldn't tell what calendar change you want — try naming the event and the new time directly.");
    return;
  }

  let proposal: Proposal<CalendarEditChange>;

  if (draft.kind === "create") {
    proposal = proposeNewCalendarEvent({ calendarId: "primary", title: draft.title, start: draft.start, end: draft.end });
  } else {
    const matchedEvent = events.find((e) => e.title.trim().toLowerCase() === draft!.eventTitle.trim().toLowerCase());
    if (!matchedEvent) {
      io.writeLine(`I couldn't find an event called "${draft.eventTitle}" on today's calendar.`);
      return;
    }

    const route = await resolveRoute("primary", matchedEvent.id);
    if (route.kind === "owned") {
      io.writeLine("That's one of my own Plan blocks — use a Mid-Day Re-Flow report to adjust it instead.");
      return;
    }

    proposal = await proposeEdit(
      "primary",
      matchedEvent.id,
      draft.kind === "move" ? { kind: "move", newStart: draft.newStart } : { kind: "resize", newEnd: draft.newEnd },
    );
  }

  io.writeLine(proposal.reason);
  let confirmAnswer: string | null = null;
  do {
    confirmAnswer = await io.readLine("Apply this change? (yes/no): ");
    if (confirmAnswer === null) return;
  } while (confirmAnswer.trim().length === 0);

  if (parseProposalAnswer(confirmAnswer) !== true) {
    io.writeLine("Okay — I won't make that change.");
    return;
  }

  const applied = await applyEdit(proposal);
  if (!applied.ok) {
    io.writeLine(`I couldn't apply that: ${applied.error.message}`);
    return;
  }

  io.writeLine("Done — updated your calendar.");
}
```
