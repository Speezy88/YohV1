# Story 6.5: File a Search Result to the Research Vault — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After Yoh returns a search result in the current chat session, Spencer can say "save that" and have it filed to the Research Vault immediately — no preview/confirm step, since the save request itself is the confirmation (AD-12).

**Architecture:** `runChatCli` tracks the most recent `SearchAnswer` (plus the query that produced it) in an in-memory, per-session variable — set whenever Story 6.4's `handleSearchCommand` succeeds, read by a new deterministic trigger recognizer, `isSaveSearchResultCommand`, checked right after `parseCreateItemCommand` (same tier as every other deterministic check, before `classifyChatIntent`/the general-qa catch-all). On match, `handleSaveSearchResultCommand` builds a `Record<string, string>` properties map using the same internal field names Story 6.3's `createPage` already recognizes for `'ResearchVault'` (`title`, `keyFindings`, `query`, `searchDate`, `sources`) and calls `createPage` DIRECTLY — no `Proposal`, no confirm step, reusing the exact `CreateNotionPageFn` binding Story 6.3 already wired into `main()`. Per AD-3, FR-29 is explicitly "a direct write, never routed through this Proposal/confirm machinery," so this story adds no new Notion-adapter surface at all — it's pure `chat-cli.ts` wiring on top of what 6.1/6.3/6.4 already built.

**Tech Stack:** TypeScript, `node:test`. No new adapter code.

**Spec:** `_bmad-output/planning-artifacts/epics.md` Story 6.5 (lines 922–943); `ARCHITECTURE-SPINE.md` AD-3 (FR-29's direct-write exception), AD-12 (Story 6.1's confirmed Research Vault property names).

3a. Add the trigger recognizer near `parseCreateItemCommand`:

```ts
/**
 * Recognizes "save/file that/this [to the (research) vault]" — the same
 * deliberately-simple starting heuristic every other trigger recognizer in
 * this file uses. Deliberately does NOT match "save my progress" or
 * similar — the trigger word must be immediately followed by "that"/"this"
 * (optionally then "to the vault"/"to the research vault"), not an
 * arbitrary object.
 */
const SAVE_SEARCH_RESULT_RE = /^(?:save|file)\s+(?:that|this)(?:\s+to\s+the\s+(?:research\s+)?vault)?\.?$/i;

export function isSaveSearchResultCommand(line: string): boolean {
  return SAVE_SEARCH_RESULT_RE.test(line.trim());
}
```

3b. Add the handler near `handleSearchCommand`:

```ts
/**
 * Files `lastSearchAnswer` to the Research Vault directly (Story 6.5 /
 * FR-29) — no `Proposal`, no confirm step (AD-3: FR-29 is a direct write,
 * the save request itself is the confirmation). Uses the query that
 * produced the answer as both the page's title and its `query` field.
 * `undefined` (no recent search this session) reports plainly rather than
 * fabricating a page from nothing.
 */
async function handleSaveSearchResultCommand(
  io: ChatCliIo,
  lastSearchAnswer: { readonly query: string; readonly answer: SearchAnswer } | undefined,
  today: IsoDate,
  createPageFn: CreateNotionPageFn,
): Promise<void> {
  if (!lastSearchAnswer) {
    io.writeLine("I don't have a recent search result to save — search for something first.");
    return;
  }

  const properties: Record<string, string> = {
    title: lastSearchAnswer.query,
    keyFindings: lastSearchAnswer.answer.answer,
    query: lastSearchAnswer.query,
    searchDate: today,
    sources: lastSearchAnswer.answer.citations.join("\n"),
  };

  const created = await createPageFn("ResearchVault", properties);
  if (!created.ok) {
    io.writeLine(`I couldn't file that: ${created.error.message}`);
    return;
  }

  io.writeLine(`Filed "${properties["title"]}" to the Research Vault.`);
}
```
